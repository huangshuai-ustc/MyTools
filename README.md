# 方寸（Fangcun）

“方寸”（英文名 `Fangcun`）是一个使用 SwiftUI 编写的本地优先多平台应用，界面语言为中文。应用把金融账户、股票、换汇、健康资料、美食地点、保密资料、个人证照和账单集中保存在本机，适合个人长期记录、查询和备份。

隐私政策：<https://huangshuai-ustc.github.io/MyTools/privacy.html>

当前包含八个工具模块：

- **金融账户**：银行账户、子账户、银行卡和信用卡账单
- **股票投资**：A 股、港股、美股的持仓、交易和分红
- **换汇记录**：换汇流水、中国银行牌价和人民币损耗
- **健康档案**：就诊、复诊、药房购药、体检、费用和附件
- **美食地图**：吃过、想吃或尚未吃的美食、店铺、地点、图片和来源
- **保密资料**：账号密码、邮箱授权、服务 Token、备份密钥和软件授权
- **证照**：身份证、护照、驾驶证、学历学位证和房产证等重要证照
- **账单**：手工记账、图片 OCR、交换文件导入和付款明细管理

## 平台与工程

- iOS / iPadOS 26.0 及以上
- macOS 26.0 及以上
- Xcode 26.0 及以上
- Swift 6.0、SwiftUI 多平台工程
- 默认 Bundle Identifier：`com.fjwyz.PersonalToolBox`，可以通过本地签名配置覆盖
- 工程文件：`MyTools.xcodeproj`
- Scheme：`MyTools`
- App 中文显示名称：`方寸`
- App 英文显示名称：`Fangcun`
- 不依赖第三方 Swift Package

源码目录、Swift 模块、Target、Scheme、本地数据目录和备份扩展名统一使用内部名称 `MyTools`，以保持源码与既有数据兼容；当前 App 对外显示名称仍为“方寸”，英文系统显示为 `Fangcun`。版本信息以工程 `Info.plist` 和应用“我的 > 关于”页面为准。

## 功能

### 工具首页

- 按模块进入“金融账户”“股票投资”“换汇记录”“健康档案”“美食地图”“保密资料”“证照”和“账单”。
- 在“我的 > 首页功能”中显示或隐藏模块，并拖动调整模块顺序。
- 首页顺序与设置页保持一致；关闭的模块不会出现在工具首页。

### 金融账户

- 支持境内银行和境外银行，首页可按“全部”“境内”“境外”筛选。
- 银行档案保存银行、支行、状态、开户时间、备注以及境外银行的 SWIFT、IBAN、地址和汇款资料。
- 支持境内和境外子账户；每个子账户单独保存类型、名称、账号、币种和“正常/异常/销户”状态。
- 支持借记卡和信用卡；银行卡可保存卡号、CVV、有效期、持卡人、卡组织、币种、状态和开卡时间。
- 信用卡可添加多份 PDF 账单，保存账单日期和备注；账单附件可以随加密备份导出和恢复。
- 首页默认隐藏停用银行；银行详情默认隐藏已销户银行卡和子账户。隐藏项目可以临时展开，不会删除数据，境内境外使用相同规则。
- 首页统计只计算当前可见的银行、未销户子账户和未销户银行卡，并显示银行、子账户、借记卡和信用卡数量。
- 支持按地区筛选、搜索银行/支行/账户类型/账号/币种/卡种/持卡人，以及按名称、开户时间、地区和卡片类别排序。
- 普通模式可以查看档案详情；完整卡号、CVV、有效期、登录密码、敏感附加字段和信用卡账单需要单独验证身份后查看。
- 银行、银行卡和子账户详情中的已填写文本支持长按复制，并显示复制提示。

### 股票投资

- 支持 A 股、港股和美股；每只股票保存市场、代码、自定义名称、买入/卖出流水和分红流水。
- 新增股票时记录首次买入日期、股数、价格和交易费用；详情页可以继续维护买入、卖出和分红。
- 卖出、编辑或删除交易时按交易日期校验任意时点的持仓不能小于零。当前持仓、持仓成本、持仓盈亏、已变现利润和总盈亏均由流水自动计算。
- 分红记录支持到账日期、分红股数、每股分红、预扣税、其他费用和备注，净分红自动计入总盈亏。
- 市场筛选入口会根据实际买入记录动态显示：没有某个市场的买入记录时不显示该市场，新增买入记录后自动出现；“全部”只包含有买入记录的股票。
- A 股、港股、美股分别使用 CNY、HKD、USD 汇总；“全部”视图可按中国银行港币和美元现汇买入价折算人民币。
- 市场概览显示持仓成本、持仓盈亏、已变现利润和资产占比；股票详情仍显示当前市值，缺少行情或汇率时显示“待同步”，不会按零估值。
- 股票页面打开时刷新行情，并在页面可见期间每 60 秒自动刷新；支持下拉刷新和工具栏手动刷新。行情失败时保留最后一次成功的价格和更新时间。
- 每条股票向右滑动可以直接进入看盘页，不要求管理员权限；支持分时、5 日、1 月、3 月、1 年、5 年和 10 年范围，以及走势图和 K 线切换。行情图会用不同颜色标注买入、卖出日期及成交价，并可展开为横屏图表；交易时段停留在分时页时每 30 秒更新一次。
- 行情服务使用公开市场接口，并按市场提供批量请求、时间校验和缺失数据兜底；原始时序行情会增量保存在本地离线文件中，但不写入业务档案或加密备份。公开行情可能延迟或暂时不可用，应以交易所和券商数据为准。
- 支持按名称或最早买入时间排序；“我的 > 设置”可以分别设置 A 股、港股和美股的涨跌颜色规则。

### 换汇记录

- 保存换汇日期、卖出币种、买入币种、价格口径、卖出金额、实际买入金额和手续费；日期按当天保存，记录按日期倒序排列。
- 支持两种价格口径：`100 买入币种 = ? 卖出币种`，或 `100 卖出币种 = ? 买入币种`。
- 理论买入金额由价格和卖出金额计算，实际买入金额由用户填写；两者差额用于分析汇率损耗。手续费按卖出币种额外支付。
- 当前支持人民币、港币、美元、加拿大元、瑞士法郎、欧元、英镑、日元、新西兰元、新加坡元、泰国铢和澳大利亚元；金融账户和换汇记录共用币种定义。
- 每笔记录按当前中国银行现汇买入价折算交易前成本和交易后人民币价值，计算人民币损耗或盈利；牌价缺失时显示“待同步”。
- 换汇概览显示记录数、涉及币种和累计结果；亏损显示“人民币总损耗”，盈利显示“人民币总盈利”。
- 支持按“全部/买/卖/换”筛选、按年份筛选、按相关币种和组合币种筛选、搜索币种名称或代码，并按月份分组。
- 提供中国银行结售汇牌价页和双向换算器，可在内置币种之间换算；牌价缓存供股票投资和换汇记录共用。
- 支持新增、编辑和侧滑删除，记录随本地档案和加密备份保存。

### 健康档案

- 健康记录支持门诊、急诊、住院、药房购药和体检。
- 就诊记录保存日期、医院、医院级别/等次/性质、科室、医生、主诉、诊断、治疗建议、费用、支付方式、标签、备注和附件；医院以外的机构不设置医院级别、等次和性质。
- 医疗机构资料库统一收录医院、药房和体检机构；编辑机构或新增记录时可以选择机构类别，记录中选择或输入已有名称时会按类别筛选并自动回填医院分类。
- 药房购药记录保存购药日期、药房、药品、购药原因、费用、支付方式、标签、备注和附件；可以作为独立记录，也可以关联到某次就诊。
- 任意门诊、急诊或住院详情可以新增多条关联复诊和关联药房购药；关联记录保留原就诊上下文，并按实际日期计入费用统计。
- 体检按轮次保存：第一次体检就是原始体检记录，后续检查通过关联体检记录添加，既可以只有一轮，也可以有多轮；每一轮都使用统一的健康记录编辑器，保存体检日期、机构、完成项目、检查结果、健康建议、关注项和附件。
- 体检“查出的问题”支持 Markdown 文本，并兼容常用的行内数学写法，例如 `$24.9kg/m^2$` 会显示为 `24.9kg/m²`。
- 费用由费用项目自动合计；支持自费、医保、医保后自费三种支付方式，金额输入支持数字和 `+ - × ÷` 及括号。
- 医疗档案首页显示年度总费用、医保支付、自费费用、机构数量和就诊/体检次数；支持切换年份。
- 支持搜索医疗机构、药房、体检机构、套餐、检查项目、关注项、科室、医生、诊断、费用项目、附件和标签，也可以按标签筛选。
- 支持照片、图片和 PDF 附件，并可分类为发票、病历、检验报告、体检报告、CT、MRI、X 光、化验单、扫描件或其他。
- iOS 使用 Quick Look 预览附件，macOS 使用系统默认查看器打开。健康详情中的文字支持长按复制。
- 首页按原始就诊事件展示复诊和关联购药数量；进入详情后查看完整关联记录。新增、编辑和删除需要管理员模式。

### 美食地图

- 记录吃过、想吃或还没吃的美食；每条记录可以保存食物名称、店名、中国省市、详细地址、地图坐标、吃过日期、标签和备注，国外地点可以不填写省市。
- 支持最多 10 张图片，以及可选的信息来源名称和链接；列表可搜索，并按状态或自定义标签筛选。
- 地图位置可以按店名或地址搜索，也可以直接在地图上点选；详情页以地图卡片显示保存的位置。
- “查看全部标记”集中展示所有已定位地点，支持选中标记后查看详情或跳转 Apple 地图；设备安装对应 App 时，也可选择高德、百度、腾讯或 Google 地图导航。
- 浏览记录、查看总地图和发起导航不要求管理员权限；新增、编辑和删除沿用统一的管理员模式。

### 管理员与敏感信息

- 首次使用时设置至少 8 位管理员密码。
- 可使用管理员密码、Face ID、Touch ID 或设备密码进入管理员模式；App 进入后台时自动退出管理员模式。
- 管理员模式统一显示状态标识，并负责新增、编辑和删除金融档案、股票、换汇记录、健康档案、医疗机构资料、美食记录、保密资料、证照和账单；备份导入导出也要求管理员权限。
- 查看敏感信息使用独立的身份验证入口，不会因此进入管理员编辑模式；认证通过后只在当前详情页临时显示。

### 保密资料

- 资料按条目管理；每个条目包含分类、标签、备注和多个可自定义字段。
- 内置登录凭据、邮箱账户、服务令牌、备份与恢复、软件授权和其他六类模板；字段名称可以自定义，输入形式支持单行或多行，是否在查看时遮罩也可单独设置。
- 保密资料默认锁定，查看需要单独验证身份；新增、编辑和删除需要管理员模式。
- 敏感字段默认遮罩，验证后显示明文；字段内容统一使用长按复制，应用不设置剪贴板过期时间，也不会主动清除复制内容。

### 证照

- 内置身份证、护照、港澳通行证、驾驶证、学历证、学位证、房产证和自定义类型；可保存证照名称、持有人、号码、签发机关、标签、备注及模板字段。出生日期不属于通用基本信息，有需要时作为自定义字段记录；旧版固定出生日期可在存储清理中无损迁移为自定义字段。
- 身份证必须选择五年、十年、二十年或长期有效，不提供“暂不设置”；五年、十年或二十年期限通过签发日期自动计算到期日。其他证照仍支持固定日期区间、长期有效和暂不设置；可以配置提前提醒天数，关闭证照模块时会撤销该模块的预约通知。
- 支持图片和 PDF 附件，并可标记为正面、反面、照片页、签证页、扫描件或其他；附件可改名、预览和随备份恢复。
- 可以从图片、PDF 或相机照片中框选区域执行中英文 OCR，再逐项确认姓名、证件号、日期、签发机关及模板字段候选；性别、民族、住址等已有字段会自动填入，识别出的其他“字段：内容”会在确认后自动创建为自定义字段，识别结果不会未经确认直接覆盖表单。
- 同一证照可以保留多个版本，并为每个版本标记正常、已过期、已遗失、已换发或已作废；主列表按证照聚合并默认展示到期日最晚的版本，版本列表同样按到期日从晚到早排列，长期有效优先、没有到期日的数据最后。详情页可查看、编辑和新增版本。
- 列表支持搜索，并按证照类型、有效期状态、证照状态和标签筛选；查看敏感详情需要独立身份验证，新增、编辑和删除需要管理员模式。

### 账单

- 账单页顶部分为“记录”和“分析”；分析按月份及币种独立统计月度支出、净支出、收入、退款、结余和交易笔数，并展示上月对比、每日支出、支出分类、商户排行及付款方式图表。
- 取消的交易不进入分析；退款从净支出中扣除，“不计收支”只统计笔数，不与其他币种或收支金额混合。
- 支持手工新增、编辑和删除支出、收入、退款与不计收支记录，转账作为交易分类保存；记录包含金额、币种、交易时间、商户、交易对方、商品说明、支付方式、付款账户、分类、状态、标签和备注。
- 支持从照片或图片文件载入付款截图，框选区域后复用 Core Vision OCR 进行中英文准确识别；识别出的金额候选、日期、商户和支付方式必须在确认后才保存，原始图片和整段 OCR 文本不会默认写入 Vault。
- 列表支持搜索和按收支类型筛选，显示本月人民币支出、收入及退款与结余；不同币种不会被错误相加。
- 内置 `com.fjwyz.mytools.bill-exchange` 版本 2 JSON 交换协议，包含来源、账户、交易时间、收支方向、金额币种、平台交易类型与分类、商户/对方及对方账号、商品、渠道、标准状态与平台原始状态、交易号、商户订单号、退款关联和原始字段；导入前提供预览，重复的“来源 + 外部交易号”会更新而不会重复累加。
- 可直接导入微信支付 XLSX 和支付宝 GB18030/UTF-8 CSV。解析器自动定位“交易时间”明细表头，只转换表头后的交易记录，姓名、账户、收支汇总、导出说明和提示等顶部内容不会进入账单；微信的“/”和支付宝的“不计收支”统一映射为不计收支，退款、关闭及处理中状态会转换为统一状态，同时保留平台原值。
- XLSX 使用系统压缩与 XML 能力读取，不增加第三方依赖；支付宝 CSV 支持引号、字段内逗号和换行。OFX、ISO 20022 `camt.053` 及各家银行卡 CSV 可继续作为外部 Adapter 接入，但不作为内部核心格式。

## 数据存储与备份

- 银行账户、银行卡、股票、换汇记录、健康档案、医疗机构资料、美食记录、保密资料、证照和账单统一保存在 App Sandbox 的 `Application Support/MyTools/local-vault.json`。当前敏感字段按 Codable 明文写入该文件，应用层加密仍是后续工作。
- 健康附件、信用卡账单 PDF、美食图片、保密资料附件和证照附件保存在 Application Support 的附件目录；本地 JSON 只保存附件元数据，备份时会一并打包附件内容。
- 日常档案使用原子写入，并在后台串行保存；App 进入后台时会等待排队中的保存完成。
- 诊断日志按本地日期保留今天和昨天；每天首次写入、查看或导出诊断日志时自动清理 T-2 及更早记录。
- “我的 > 设置 > 存储与数据”会预览当前已编译且已开启模块中的不适用字段值，管理员确认后可定向清理；清理结果会写回本地 Vault，并在已开启 iCloud 同步时参与下一次 CloudKit 对账。关闭模块和未编译模块的不透明数据不会被扫描或修改，已经导出的旧备份也不会被改写。
- 管理员可以从“我的”页面导出或导入 `.mytools` 加密备份。备份使用 PBKDF2-HMAC-SHA256 派生 256 位密钥，并使用 AES-GCM 加密；当前唯一支持的备份格式版本为 `1.0`，同时记录备份中包含的工具模块。
- 当前只读取最新的本地容器和备份载荷结构，不再兼容更早的顶层 `VaultData`、旧体检嵌套批次或单选医疗机构字段。
- 备份密码至少 8 位；密码页默认填入当前管理员密码，也可以清除后输入独立的自定义备份密码。自定义密码不会由 App 保存，丢失后无法解密备份。
- 导入备份采用增量合并，不会清空未包含在备份中的工具模块或本地数据。备份中包含的模块按记录 ID 合并：已有同 ID 记录使用备份内容更新，新记录追加；对应的健康附件、信用卡账单、美食图片、保密资料附件和证照附件会一并恢复。
- 可在“我的 > 设置 > iCloud 同步”中主动开启 CloudKit 私有数据库同步；该功能默认关闭。银行、银行卡、股票持仓、换汇、健康档案、医疗机构、美食记录、提醒、保密资料、证照、账单和附件按记录增量同步，多个设备需登录同一 Apple 账户。
- 首页模块开关是备份和 CloudKit 的模块边界：关闭模块不会参与备份导入/导出、上传或远端变更合并，也不会因为快照缺失而删除云端历史；重新开启后再恢复该模块的对账。
- 本地档案始终是离线数据源。股票行情、汇率缓存、诊断日志、管理员会话和设备认证状态不会上传；附件使用 `CKAsset`，业务 JSON 写入 CloudKit 的加密字段。关闭同步不会删除本机资料。

## 安全边界

- 当前本地 JSON 档案没有应用层加密，卡号、CVV、保密资料字段和证件号码可能以明文存在于本地文件中；图片与 PDF 附件也以未加密文件单独存放在同一 Application Support 下。iOS 文件使用系统文件保护。
- App 沙盒隔离和敏感信息界面遮罩不能替代应用层加密。管理员密码当前以 SHA-256 摘要保存在 `UserDefaults`，没有独立盐值。
- 导出备份文件经过密码加密；默认使用管理员密码，用户可以清除默认值并设置独立备份密码。管理员密码哈希保存在 `UserDefaults`，可用的明文备份密码会尝试保存在本机 Keychain 中以支持生物识别后的默认填充。
- CloudKit 同步是可选的数据副本与多设备合并能力，不能替代独立的 `.mytools` 加密备份。切换 Apple 账户，或用户从 iCloud 清除方寸数据时，App 会保留本机资料并自动关闭同步，避免误传到其他账户或重新上传已清除的数据。

## 打开与运行

1. 在 Xcode 中打开 `MyTools.xcodeproj`。
2. 选择 Scheme `MyTools`。
3. 本仓库默认配置使用作者的 Bundle Identifier，Xcode Cloud 可直接据此归档；其他开发者在真机安装前，应把 `Config/Signing.local.xcconfig.example` 复制为 `Config/Signing.local.xcconfig`，填写自己的 `DEVELOPMENT_TEAM` 和唯一 Bundle Identifier。
4. 在 Apple Developer 与 Xcode 的 Signing & Capabilities 中为这个 Bundle Identifier 启用 iCloud/CloudKit、Push Notifications 和 Background Modes，并创建 `iCloud.<你的 Bundle Identifier>` 容器。`MyToolsRelease.entitlements` 会按构建时的 Bundle Identifier 引用该容器。
5. `Signing.local.xcconfig` 不会提交到 Git。仓库中的 `Shared.xcconfig` 保留本 App 的默认 Bundle Identifier，其他开发者使用本地配置覆盖它；Team ID 和签名证书仍由 Xcode Cloud 或本机签名设置提供。
6. `Config/Shared.xcconfig` 中的 `MYTOOLS_ENABLE_*` 行是业务模块唯一编译开关，注释某一行即可构建不含该模块代码、页面、服务注册、备份和 CloudKit 参与逻辑的产品变体；`MYTOOLS_COMPILED_FEATURES` 由这些开关汇总生成，不要在其他构建设置中维护第二份清单。
7. 选择 iPhone、iPad 或 My Mac 后运行。

首次开启同步后，用开发签名运行 App 并新增或修改一条记录，确认 CloudKit Dashboard 的 Development 环境出现 `MyToolsEntity` 记录类型和 `MyToolsData` 自定义 Zone。上传 TestFlight 或 App Store 前，必须在 CloudKit Dashboard 执行 **Deploy Schema Changes to Production**；否则开发环境正常而正式版本无法读写。

首次使用建议：先进入“我的”设置管理员密码，再从“金融账户”“股票投资”和“健康档案”录入数据，最后导出一份 `.mytools` 备份。

## GitHub 仓库文件

仓库需要保留源码、资源、`Info.plist`、`MyTools.xcodeproj/project.pbxproj`、共享 Scheme、工作区基础文件以及 `Config/Shared.xcconfig`。这些文件共同描述 Target、编译源文件、资源、系统权限和构建设置，仅上传 Swift 文件无法直接还原可编译工程。

以下内容不应提交：`xcuserdata`、`*.xcuserstate`、`Signing.local.xcconfig`、`DerivedData`、`build`、`.DS_Store`、日志和本地密钥配置。项目的 `.gitignore` 已覆盖这些内容。

任何人 clone 仓库后都可以使用模拟器构建。安装到 iPhone、iPad 或签名运行 macOS App 时，每位开发者都必须使用自己的 Apple Developer Team 和唯一 Bundle Identifier；Apple 不允许第三方直接复用仓库作者的开发签名。

## 工程结构

```text
MyTools/
├── Config/                 # 公共构建配置和本地签名示例
├── MyTools.xcodeproj/
├── README.md
└── MyTools/
    ├── App/                 # 启动、组合根、导航、模块目录和应用设置
    ├── Core/                # 不属于单个模块的认证、附件、备份、同步、持久化和基础服务
    └── Features/            # Finance、Stocks、CurrencyExchange、Health、FoodMap、Secrets、Documents、Bills
```

主要入口和服务：

- `App/Modules/ToolModule.swift`：工具模块目录、能力声明、备份/同步参与配置；新增模块先在这里登记。
- `Config/Shared.xcconfig`：业务模块编译清单；新增模块必须增加独立的 `MYTOOLS_FEATURE_*` 标记并覆盖整个 Feature 源码。
- `App/Composition/AppStore.swift`：模块 Store 装配、初始加载、持久化快照和备份恢复协调。
- `App/Composition/ModuleStoreContracts.swift`：模块生命周期、数据变更通知和冗余字段清理参与者接口；清理规则由拥有数据的 Feature Store 实现。
- `Features/*/{Domain,Application,Presentation}`：各业务模块按领域模型、应用状态和界面分层；股票行情 Provider 位于 `Features/Stocks/Infrastructure`。
- `Core/Persistence`、`Core/Attachments`、`Core/Backup`、`Core/CloudSync`：本地档案、通用附件、加密备份和可选的 CloudKit 增量同步基础能力。
- `Core/Authentication`：管理员模式、身份验证和敏感信息验证。
- `Core/Currency`：所有模块共用的币种定义和中国银行牌价能力；`StockQuoteService.swift` 仍只属于股票模块。
- `Core/OCR`：基于 Vision 的图片/PDF 文字识别、归一化区域选择和可扩展语言配置；设置中的“文字识别测试”是暂时的验证入口，不属于任何可关闭业务模块。

## 架构边界

- `Core` 保存不归属于单个可关闭工具模块的基础能力；基础能力不能依赖某个业务模块的可见状态。
- `Features/*/Domain` 只保存业务模块的 Codable 数据和可确定计算，不直接访问文件、网络或 SwiftUI 状态。
- `AppStore` 是主线程上的应用状态协调器，负责把编辑结果交给持久化、附件和行情服务；页面不直接写本地文件。
- `SecureStore` 负责本地 JSON 的读写，`VaultPersistenceCoordinator` 在串行后台队列合并写入，并把失败错误码回传给应用状态。
- `AttachmentStore` 负责单个附件的文件生命周期；备份处理器负责健康、金融、美食地图、保密资料和证照的附件映射，五个模块共用同一套文件安全属性和预览包装器。
- `AuthManager` 只负责管理员会话和身份验证，敏感信息查看使用独立的验证入口，不把查看权限混入编辑会话。
- 股票和换汇模块都可以使用基础牌价能力；只有两个模块均关闭时才停止牌价刷新。模块开关仍分别控制各自页面、数据备份、提醒和模块专属后台任务。
- 即时报价、历史行情和牌价服务分别承担网络请求与解析；看盘原始时序写入独立离线缓存，不进入 `AppStore` 的业务 Vault 或加密备份。

## 当前限制

- 股票行情依赖公开接口，不提供交易所级低延迟保证；分红、拆股和税费调整需要手动维护。
- 普通本地档案、保密资料和证照目前没有应用层加密；项目包含独立 `MyToolsTests` Target，行情、备份、医疗规则、证照和模块 Store 已有自动化回归测试，跨平台 UI 仍需设备验证。
- 健康档案目前记录费用、附件和体检项目，血压、血糖、BMI、心率等结构化健康指标尚未加入。
