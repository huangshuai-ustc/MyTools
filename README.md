# 方寸（Fangcun）

“方寸”（英文名 `Fangcun`）是一个使用 SwiftUI 编写的本地优先多平台应用，界面语言为中文。应用把金融账户、股票、换汇、健康资料、保密资料和证照资料集中保存在本机，适合个人长期记录、查询和备份。

官网首页：<https://huangshuai-ustc.github.io/MyTools/>  ·  营销网址：<https://huangshuai-ustc.github.io/MyTools/marketing.html>  ·  技术支持：<https://huangshuai-ustc.github.io/MyTools/support.html>  ·  隐私政策：<https://huangshuai-ustc.github.io/MyTools/privacy.html>

当前编译六个工具模块；收支账单和体彩开奖已在 `Config/Shared.xcconfig` 中关闭编译（代码保留），美食地图和合伙记账已移除：

- **金融账户**：银行账户、子账户、银行卡和信用卡账单
- **股票投资**：A 股、港股、美股的持仓、交易、分红和投资资金台账
- **换汇记录**：换汇流水、中国银行牌价和人民币损耗
- **健康档案**：就诊、复诊、药房购药、体检、费用和附件
- **保密资料**：账号密码、邮箱授权、服务 Token、备份密钥和软件授权
- **证照**：身份证、护照、港澳通行证、驾驶证、学历学位证、房产证、出生医学证明、预防接种证和职业资格证书等重要证照

## 平台与工程

- iOS / iPadOS 26.0 及以上
- macOS 26.0 及以上
- Xcode 26.0 及以上
- Swift 6.0、SwiftUI 多平台工程
- 默认 Bundle Identifier：`com.fjwyz.PersonalToolBox`，可以通过本地签名配置覆盖
- 工程文件：`MyTools.xcodeproj`
- Scheme：`MyTools`
- App 中文显示名称：`方寸`
- App 英文显示名称：`Fangcun`
- 不依赖第三方 Swift Package

源码目录、Swift 模块、Target、Scheme、本地数据目录和备份扩展名继续使用内部名称 `MyTools`。对外构建产物及可执行文件名为 `Fangcun`（安装包 `Fangcun.app`），中英文 `CFBundleName` 与 `CFBundleDisplayName` 分别为“方寸”和 `Fangcun`，未匹配本地化时使用 `Fangcun`。Bundle Identifier 保持不变；安装脚本应使用新的产物路径。版本信息以工程 `Info.plist` 和应用设置页面为准。

## 功能

### 工具首页

- 按模块进入“金融账户”“股票投资”“换汇记录”“健康档案”“保密资料”和“证照”。
- 在“我的 > 首页功能”中显示或隐藏模块，并拖动调整模块顺序。
- 首页顺序与设置页保持一致；关闭的模块不会出现在工具首页。

### 标签规范

- 健康档案、保密资料、证照（及未编译的账单）统一使用标签能力：输入时以中文逗号 `，` 分隔，保存时自动去除空白、去重并兼容旧版逗号/顿号分隔数据。
- 标签在列表、详情和筛选入口中以灰色背景胶囊显示，不再用一段顿号连接的普通文本；选中的筛选标签使用强调色胶囊。
- 每个功能独立持久化已使用过的标签。编辑记录时会显示该功能的历史标签建议，点击即可复用；删除记录不会清空标签建议库。
- 上述功能的列表都支持标签搜索；健康档案、保密资料和证照均可按标签筛选。

### 列表行规范

- 详情、新增和编辑页面中的标准单行统一使用相同的内容高度与整行高度地板，视觉密度接近系统裸 `LabeledContent`；普通文本、用户输入、日期、选择器、开关、状态徽章、菜单和按钮不会因控件类型不同而出现两档行高。iOS/iPadOS 随 Dynamic Type、macOS 随 App 字号设置同步增高；地址、备注、算式预览和记录卡片等真实多行内容仍按实际内容自适应增高。
- 换汇记录、健康档案、保密资料和证照资料（以及未编译的收支账单、体彩开奖）统一使用无感增量列表：默认先显示 30 条，滑动到当前末条时自动继续加载 30 条，不插入额外按钮或加载行；搜索或筛选条件改变后回到首屏。各功能只声明自己的分页条数，触底、上限和重置规则由 Core 统一处理。
- 所有模块的左滑删除和右滑操作统一使用 `Core/UI/ListViewModifiers.swift` 中的 `AppSwipeActions` 配置；删除动作统一显示为红色“删除”，主要操作和辅助操作的颜色及是否允许全滑由公共 modifier 统一控制，各模块不得直接写 `.swipeActions`。
- 展示文字统一使用 `Core/UI/ListViewModifiers.swift` 中的 `.appFont()` 语义字体：iOS/iPadOS 保持系统原生字体样式和 Dynamic Type，macOS 按“外观与文字”中的用户字号统一缩放显式标题、正文、说明、等宽数字以及未单独指定样式的系统控件；列表行高度和单一导航标题同步适配字号，避免同页混用两套字号或标题重复。

### 金融账户

- 首页按银行、券商和支付机构分组；银行地区筛选与银行总览放在银行分组内部，仅筛选银行。机构列表统一以名称和账户概况两行呈现，券商显示账户／入金资料数量，支付机构显示币种账户／收款资料数量。

- 统一管理银行、证券、支付和其他机构；每个机构只有一个类型（银行、券商、支付、其他），类型决定它使用哪种专属资料和编辑页，不限制账户或收款资料数量。模型与持久化边界见 [FINANCE_MODEL.md](FINANCE_MODEL.md)。
- 银行分组内提供银行、借记卡、信用卡、子账户四项总览（只统计当前地区筛选下可见的银行、未销户卡片和非销户子账户）；在用银行直接列出，停用银行从“N 家停用银行”展开。银行在卡片全部销户、且没有正常状态的子账户时归档；没有卡片的银行还需机构状态为异常或销户才归档，因此仅销户账户不会让银行归档；异常状态的子账户不算在用。券商、支付和其他机构按分组全部列出，首页不区分归档；其他机构已有账户或卡片且全部销户时，详情页标注“已归档”。空档案及仅有登录资料的档案保持可见。
- 查看页仅显示非空栏目；添加、删除和管理位于编辑页。子账户挂在银行账户下（`FinancialAccount.subaccounts`），用于社保、公积金、个人养老金、投资、外汇等有独立账号的账户，境内与境外银行分别提供对应的子账户类型。往来账户与支票账户分开，一个账户可支持多个币种。
- 银行账户列表展示类型、首尾遮蔽账号和状态；账户与卡片共用正常／异常／销户状态。已销户账户和卡片分别临时展开，展开按钮位置固定。
- 银行收款资料支持任意多组字段与多币种；支付机构的每个币种账户支持多套收款资料，可分别新增、编辑和删除。收款资料不保存渠道、来源核对、常用标记或历史版本。支持关联实际账户；分享包含字段与备注。
- 登录信息直接显示，标签与内容左对齐；敏感字段旁提供身份验证后的查看按钮，隐藏值不能复制。已填写文本继续长按复制。模板缺键使用历史默认，明确空模板保持为空。
- 新卡未指定网点时带入机构开户网点，用户指定的网点不会被覆盖。网点名称和定位图标提供导航链接：有已存坐标时按坐标导航，无坐标时在所选地图 App 中按网点名称搜索。选点地图有已存坐标时显示网点，否则以手机当前定位为中心，必须由用户选定位置后才能保存，不会写入任何默认坐标。地图复用 Core 组件。
- 银行卡保留借记／信用、发卡组织、附加卡号、有效期、开卡日期和信用卡 PDF 账单。银行卡数据模型可记录关联账户（`linkedFinancialAccountIDs`），账户详情会显示关联卡片；编辑页暂未提供设置关联的入口，删除账户时自动解除关联。
- 编辑使用草稿，机构保存校验完整草稿及关联卡片快照，单卡编辑校验该卡；冲突拒绝覆盖。普通字段直接展开，多选控件显示已选摘要，币种优先人民币、港币、美元。
- 附件导入在后台执行；取消编辑复用附件会话清理新文件和恢复重命名，已提交附件的删除等待成功持久化及全局引用检查。
- 本地资料按模块解码；不可读模块保留原始载荷与附件引用、暂停编辑及同步，不影响其他模块读写。所选模块不可读时拒绝正常备份导出，避免将故障导出为空数据。

### 股票投资

- iPhone 在持仓市场开市且系统允许实时活动时，会自动在锁屏和灵动岛显示当前开市市场的原币持仓市值、当日盈亏、涨跌幅及行情更新时间；前台复用股票模块统一的 60 秒行情节拍更新，收市、隐藏股票模块或无持仓时结束。App 挂起后只在系统投递后台刷新时更新，持续后台逐分钟更新需要后续接入 ActivityKit 服务端推送。
- 持仓、看盘和归档列表默认按股票代码排序，不按名称排序。
- 分时刷新先保存本轮可用行情，再独立补齐指标所需的五日历史；补齐失败不会丢弃已取得的分时。美股备用源延迟并发启动，避免主源超时耗尽备用源的请求预算。
- 离线图表缓存 v6/v7 升级会保留日线历史，并为原文件保存恢复副本；无法识别或损坏的文件保留且禁止覆盖，新行情可暂存内存。分钟数据仍按最近七个交易日保留，日线历史不受该裁剪规则影响。
- 离线图表缓存 v9 按股票拆成日线与分钟两个文件，技术指标与派生序列不落盘、读取时由 OHLCV 重建；v8 单文件自动拆分。内容未变不写盘，分钟与最新日线的改动分别按 10 分钟、30 分钟合并写入，历史日线修正立即写入；进入后台与收到内存警告时先落盘待写部分，内存警告还会释放已渲染快照与常驻缓存。
- 每个行情数据源（按 host）独立熔断：连续 4 次超时、连接失败或 429/5xx 后冷却 2 分钟，再次失败依次翻倍、最长 10 分钟，成功一次即复位；主动取消（-999）、离线和挂起期间超时的请求不计入失败；其中取消与挂起只记 INFO，离线仍记 WARN。

- 早期版本的“资金”页已移除，股票首页只有“持仓”“看盘”两页。已保存的外部入金、出金和资金损耗记录（`StockCashFlowRecord`）继续随股票模块保存、备份和同步，但当前没有查看或编辑入口。

- 休市后仍可手动刷新行情与分时缓存；单股页面仅补当前股票。自动收盘补刷按实际报价时间确认完成，未到收盘的数据仍可重试；图表接收逐步补齐的分钟数据，不将“休市”视为缓存已经完整。
- 休市手动刷新先检查最近完整交易时段的报价时间、常规收盘分钟和（美股）已结束盘后数据；已覆盖的股票不发请求，只补不完整的股票，并在诊断日志记录检查、图表补刷数和报价补刷数。

- 行情页和持仓详情页右上角仅保留前往同一股票另一页面的图标，刷新统一使用整页下拉。行情页及全屏图不提供切换股票菜单，切换股票从列表进入。

- “设置 > 股票投资”支持把当前持仓或全部持仓导出为 XLSX 工作簿：当前仅含仍持有股份的股票，全部包含历史清仓和已存档股票，排除从未持有的纯看盘股票。工作簿分两张表：“原始记录”逐条列出用户录入的交易与分红，“持仓汇总”每只股票一行，含原币成本、市值、盈亏、分红和快照时间；派生数值与原始流水分表存放，避免把计算结果误当账本事实。缺失行情留空，不触发网络刷新。这是可读报表，不是可恢复备份。股票代码按文本单元格写入，保留前导零。

- 分市场顶部总览的计价可在“设置 > 股票投资”选择市场货币（默认）或人民币；下方分市场明细保持原币，“全部”顶部总览始终用人民币。涨跌颜色通过市场切换器编辑，保留各市场独立偏好。
- 详情页点击标题菜单进入名称编辑，右上角不再单独放修改名称按钮。交易金额下方显示“成交金额 + 买入费用”或“成交金额 − 卖出费用”的具体表达式。交易日期和可选的成交时间一律按北京时间填写，保存到分钟，港股和美股所属的市场交易日由 `StockMarketClock` 从北京时间自动换算（美股夜间成交需填写成交时间，否则按北京日期对应的同日期美股交易日处理）；未填写的旧记录继续按成交价与同日顺序推定，推定结果不会写回原始流水。
- 成本按移动加权平均计算：买入金额和费用计入总成本，卖出按当时平均成本结转；单股成本为剩余成本除以股数。历史曲线使用同一算法，中间计算使用 Decimal、不按显示精度舍入，清仓结清剩余成本。原始交易不改写。

- 股票首页的“持仓总价值走势”从持仓页工具栏的走势图标进入，支持分时、5 日、日K、周K、月K、季K和年K；页面通过“合计、A 股、港股、美股”选择唯一查看目标，选择具体市场后还可在该市场全部持仓与任一单只股票之间切换。折线和组合 K 线均针对当前唯一目标绘制，组合 K 线按持仓数量汇总底层行情的开、高、低、收价值，其中开盘和收盘是真实组合价值，最高和最低是各股最高、最低价按持仓数量相加的包络近似（各股见顶、见底时间不同，影线会比真实组合略长；日K历史没有分钟数据，无法逐分钟汇总出真实高低）；当天的 K 线只在该市场交易日用实时价补出，并把高低扩到包含实时价；图表按真实日期对齐，所有周期支持拖动选点，曲线颜色与股票市场标签保持一致，人民币合计使用单独颜色。同日买入后卖出的短暂持仓会按交易顺序映射到分钟柱并显示，不会因日期相同而直接净额抵销。图中蓝色虚线是持仓成本参考线：分时和 5 日按交易事件切成台阶，持仓价值与成本在同一个成交分钟生效；用户未填写成交时间时才使用统一推定分钟，不按自然日对齐；台阶上标注各段成本，标签按当前图表的实际屏幕宽度和文字宽度去重，放不下时优先保留最新成本。日K、周K、月K、季K和年K一律按每根 K 线的成本画成连续折线、不标数值，与蜡烛的粒度一致，不再在长周期里混用台阶。

- 支持 A 股、港股和美股；每只股票保存市场、代码、自定义名称、买入/卖出流水和分红流水。

- 新增股票支持按中文名称、英文名称或股票代码模糊搜索，候选结果按当前市场和交易所筛选，并标识交易所/证券类型；同一代码的多源结果会合并，美股使用原生正式名称和规范代码回填，中文简称优先使用券商返回的短名称，不再把搜索关键字当作简称。候选行将规范代码放在正式名称右侧的标签中，第二行显示中文简称和交易所/证券类型，减少候选高度。点击候选时只自动回填代码，股票名称仍由用户自行填写，不会把候选的正式名称写入自定义名称。候选排序依次考虑代码/正式名称精确匹配、中文名称完整/后缀/前缀/包含匹配、普通股优先于 ETF、主板交易所优先于 OTC、数据源相关顺序和稳定的热门代码兜底；例如“可乐”按 `KO`、`PEP`、`COKE`、`CCEP`、`KOF`、`CCOJY` 展示，“可口可乐”和“可口”也会把 `KO` 主股票置前。搜索服务没有公开统一的实时热度分数，因此不按实时成交量改变顺序；未找到结果时会明确提示，也可以继续手工输入代码保存。
- 新增股票默认记录首次买入日期、股数、价格和交易费用；打开“仅看盘”后可只保存股票代码和行情信息，详情页可以继续维护买入、卖出和分红。
- 买入记录区分成交金额、买入费用和买入总成本，买入费用进入持仓成本；卖出记录区分成交金额、卖出费用和卖出净回款，卖出费用从回款中扣除。卖出、编辑或删除交易时同时按“交易日期 + 同日顺序”和“成交时刻”两条时间轴校验任意时点的持仓不能小于零；当前持仓、持仓成本、持仓盈亏、已实现收益和总盈亏均由流水自动计算。
- 分红记录支持到账日期、分红股数、每股分红、预扣税、其他费用和备注，并明确显示税前分红与净分红收入；预扣税和其他费用抵减分红，净分红自动计入已实现收益与总盈亏。

- 股票首页底部有“持仓”“看盘”两个入口，由系统标签栏绘制：持仓页只放 `currentShares > 0` 的股票，顶部大字显示人民币净清算价值与当日盈亏，下方固定展开持仓总盈亏、已实现收益、累计总收益三列以及各市场概览（大字已有的净清算价值与当日盈亏不再重复列出）。三列与下方每个市场概览同宽同形，互为加法关系：持仓总盈亏（未落袋，全部市场折算合计，「总」用于区分市场概览里那一列）加已实现收益（卖出实现的盈亏与净分红）等于累计总收益；已实现收益不依赖行情，缺行情时另外两列显示“待同步”而它照常给出数字。一支持仓都没有时不显示持仓页，只保留“看盘”。看盘页列出全部未存档股票，持仓股票默认也在其中，清仓后的股票保留原有交易和分红历史并继续留在看盘页；市场筛选下方一行按市场显示当前是交易中、盘前交易、盘后交易还是已休市，筛选到具体市场时只显示该市场；美股在盘前、盘后时段的行内价格、涨跌额和涨跌幅一律取**当天**的扩展时段数据，盘中和休市用常规报价，时段由顶部这一行统一说明，不在每条记录里重复标注。价格、涨跌额和涨跌幅始终来自同一组数据：常规报价三者都取行情源，扩展时段三者都取由同一基准派生的盘前/盘后结果，三者缺任意一个（含行情源当天还没发布盘前数据、缓存里只剩上一交易日的盘前）就整组回退到常规报价，不做拼接。顶部大字、三列汇总、各市场概览和资产占比与持仓行用的是同一份报价：市值、当日盈亏、持仓盈亏、当日涨跌幅的分母都由它派生，所以“总览等于各行之和”是算法上成立的，不会出现上面按昨收、下面按盘前的两套口径。相应地，美股盘前、盘后时段顶部的净清算价值与当日盈亏也会随扩展时段成交跳动，这是为了口径一致刻意接受的；当日盈亏在盘前描述的就是盘前这一段的涨跌，而不是前一个交易日的。盈亏类金额一律带正负号，不靠颜色单独表达方向（各市场涨跌配色可配，红绿含义不同）。持仓与看盘页共用市场筛选和搜索，切页时筛选状态保持不变。看盘页每行带一条只读本地缓存绘制的当日分时迷你图，画的一定是**该行报价所属的那个时段**：美股盘前画当天盘前、盘后在当日盘中之后接上当天盘后；行内因为缺当天数据而回退到常规报价时，迷你图也跟着回退，改画最近一个已收盘时段的完整走势——此时行内价格正是那一段的收盘，颜色、虚线零轴、横坐标三者仍然同源。盘中只画当天的盘中，因为旁边的价格是实时的，换成别的交易日必然矛盾，缺数据就留等高空位；休市同样画最近一个已收盘时段（A 股午休算休市，此时「最近一个交易日」就是今天，上半场不会消失）。可以整段回看的交易日只有当天和本市场最近一个已收盘交易日，更早的缓存配不上一个刚刷新过的报价，宁可留空。图中的水平虚线是涨跌零轴，直接由该行报价推出（价格 − 涨跌额），与价格色块、涨跌额和涨跌幅永远同一个基准；不从分时缓存的 `previousClose` 另算——盘前的零轴是特判出的上一结算收盘，两者常常差一个交易日，分开算会出现「涨了 0.25% 但虚线压在折线上方」。报价缺涨跌额时不画虚线。横坐标固定为本时段的全部交易分钟并按“累计在盘分钟”计算，因此 A 股午休不会留出空档，折线随时间从左往右生长、右侧尚未走完的部分留白；名称、迷你图和报价三列都靠左固定宽度，跨行对齐成竖线，行尾留出弹性空位；没有缓存时留等高空位、不额外请求行情。对已经没有持仓、也不想继续看盘但需要保留历史的股票，可以左滑使用“存档”。有过交易或分红记录的股票不提供删除：删除会连同全部交易与分红一起抹掉且没有撤销，清仓后请用“存档”把它移出看盘列表；仍在持仓的股票连存档也不给（存档只接受零持仓，否则总览合计里会藏着一只列表上看不到的股票），先在详情页卖出。真要彻底删掉一只误录的股票，先在详情页把它的交易与分红删净，记录清空后删除操作会自己回来；从未有过任何记录的纯看盘股票一直可以直接左滑删除。存档只隐藏列表和行情刷新，不删除记录，也不改变总盈亏、已实现盈亏或备份/CloudKit 同步。“历史股票”由看盘股票列表底部的显隐按钮展开，没有归档股票时不显示入口，可左滑取消归档。

- 支持两种价格口径：`100 买入币种 = ? 卖出币种`，或 `100 卖出币种 = ? 买入币种`。
- 理论买入金额由价格和卖出金额计算，实际买入金额由用户填写；编辑页并列显示“理论买入”和“实际买入”供核对，两者差额不单独计算或保存。手续费按卖出币种额外支付。
- 当前支持 24 个币种：人民币、港币、美元、加拿大元、瑞士法郎、欧元、英镑、日元、新西兰元、新加坡元、泰国铢、澳大利亚元、澳门元、匈牙利福林、菲律宾比索、阿联酋迪拉姆、捷克克朗、丹麦克朗、以色列新谢克尔、挪威克朗、波兰兹罗提、瑞典克朗、乌干达先令和南非兰特；金融账户和换汇记录共用币种定义（`Core/Currency/CurrencyCode.swift`）。
- 每笔记录按当前中国银行现汇买入价折算交易前成本和交易后人民币价值，计算人民币损耗或盈利；牌价缺失时显示“待同步”。
- 换汇概览卡片标题固定为“当前累计损耗”，数值带正负号：负号表示损耗、正号表示盈利；下方显示记录数和涉及币种。部分记录缺少牌价时只合计已知部分，并提示缺牌价的笔数。
- 支持按“全部/买/卖/换”筛选、按年份筛选、按相关币种和组合币种筛选、搜索币种名称或代码，并按月份分组。
- 提供中国银行结售汇牌价页和双向换算器，可在内置币种之间换算；牌价缓存供股票投资和换汇记录共用。
- 支持新增、编辑和侧滑删除，记录随本地档案和加密备份保存。

### 健康档案

- 健康记录支持门诊、急诊、住院、药房购药和体检。
- 就诊记录保存日期、医院、医院级别/等次/性质、科室、医生、主诉、诊断、治疗建议、费用、支付方式、标签、备注和附件；医院以外的机构不设置医院级别、等次和性质。
- 医疗机构资料库统一收录医院、药房和体检机构；编辑机构或新增记录时可以选择机构类别，记录中选择或输入已有名称时会按类别筛选并自动回填医院分类。
- 药房购药记录保存购药日期、药房、药品、购药原因、费用、支付方式、标签、备注和附件；可以作为独立记录，也可以关联到某次就诊。
- 任意门诊、急诊或住院详情可以新增多条关联复诊和关联药房购药；关联记录保留原就诊上下文，并按实际日期计入费用统计。
- 体检按轮次保存：第一次体检就是原始体检记录，后续检查通过关联体检记录添加，既可以只有一轮，也可以有多轮；每一轮都使用统一的健康记录编辑器，保存体检日期、机构、完成项目、检查结果、健康建议、关注项和附件。
- 体检“查出的问题”支持 Markdown 文本，并兼容常用的行内数学写法，例如 `$24.9kg/m^2$` 会显示为 `24.9kg/m²`。
- 费用由费用项目自动合计；支持自费、医保、医保后自费三种支付方式，金额输入支持数字和 `+ - × ÷` 及括号。
- 医疗档案首页显示年度总费用、医保支付、自费费用、机构数量和就诊/体检次数；支持切换年份。
- 支持搜索医疗机构、药房、体检机构、套餐、检查项目、关注项、科室、医生、诊断、费用项目、附件和标签，也可以按标签筛选。
- 支持照片、图片和 PDF 附件，并可分类为发票、病历、检验报告、体检报告、CT、MRI、X 光、化验单、扫描件或其他。
- iOS 使用 Quick Look 预览附件，macOS 使用系统默认查看器打开。健康详情中的文字支持长按复制。
- 首页按原始就诊事件展示复诊和关联购药数量；进入详情后查看完整关联记录；就诊信息和费用信息在详情中以总览网格展示，没有复诊、购药、附件或费用明细记录时对应分区不显示。新增、编辑和删除由页面直接提供。

### 敏感信息

- `AuthManager` 通过 LocalAuthentication 使用设备密码或生物识别临时揭示敏感详情；验证状态不形成管理员会话，也不控制新增、删除或备份入口；编辑页会显示明文，因此锁定状态下打开已有条目的编辑页（含证照新增版本）前也要先验证。

### 保密资料

- 资料按条目管理；每个条目包含分类、用途（个人/工作）、标签、备注和多个字段，首页与详情会以用途和标签胶囊展示分类信息。
- 内置登录凭据、邮箱账户、服务令牌、备份与恢复、软件授权和其他六类模板；登录凭据默认包含 URL、用户名和密码。
- 字段模板编辑器只显示字段名称输入和字段类型选择（文本、网址、日期）；已有模板字段右滑可显示/隐藏内容或编辑名称，左滑删除字段，长按可拖动调整顺序，不显示常驻拖动柄。详情页始终按当前分类模板计算显示状态，模板修改会同时作用于已有条目和新条目。
- 字段编辑采用左侧字段名、右侧内容的紧凑布局，输入内容出现换行时自动切换为多行文本；字段名固定为模板名称，需从右滑操作进入“编辑名称”或切换内容显隐，字段内容默认遮罩。新增条目会使用当前分类模板初始化字段，切换分类时会立即替换为目标分类的模板字段。
- 可从保密资料首页导入 Apple 密码 App 导出的 CSV；`.numbers` 示例需要先在 Numbers 中导出 CSV。导入会先预览条目，并自动跳过重复登录凭据。
- 保密资料默认锁定，查看和编辑已有条目需要单独验证身份；新增和删除由页面直接提供。
- 敏感字段默认遮罩，验证后显示明文；字段内容统一使用长按复制，应用不设置剪贴板过期时间，也不会主动清除复制内容。

### 外部数据导入入口规范

- 外部数据导入不设置长期显示的独立按钮，避免低频操作占用首页和工具栏空间。
- 需要同时支持“新建”和“导入”的模块，将导入作为右上角添加按钮的长按操作；短按添加按钮保持原有的新建行为。
- 长按后先显示“从文件导入”入口，再通过二级菜单选择具体来源，例如 Apple 密码 CSV。
- 新增其他外部数据导入功能时沿用同样的入口层级，不在列表分类区域或右上角额外放置常驻导入按钮。

### 证照

- 内置身份证、护照、港澳通行证、驾驶证、学历证、学位证、房产证、出生医学证明、预防接种证、职业资格证书和自定义类型；可保存证照名称、持有人、号码、签发机关、必填签发日期、标签、备注及模板字段。出生医学证明记录新生儿与父母、出生信息和签发机构；预防接种证记录受种者、监护人、接种单位和接种记录；职业资格证书记录职业/工种、资格类别与等级、从业范围及注册或复审信息。出生日期不属于通用基本信息，有需要时作为自定义字段记录；旧版固定出生日期可在存储清理中无损迁移为自定义字段。
- 证照“其他信息”采用与保密资料一致的字段编辑体验：字段名、输入形式（文本/网址/日期）和查看时隐藏内容均可配置；单行/多行不设独立选项，字段值包含换行时自动使用多行布局，否则统一使用标准单行行高。字段和模板字段支持右滑显隐/改名、左滑删除和长按拖动排序。每种证照类型都有独立字段模板，模板修改会同步已有字段的显隐设置，新建证照按当前模板生成空白字段；模板随本地档案、加密备份和 iCloud 同步保存。
- 所有证照必须填写签发日期。身份证可选择五年、十年、二十年或长期有效；护照和港澳通行证按五年或十年期限记录；驾驶证按六年、十年或长期有效记录。固定期限均从签发日期计算：身份证、港澳通行证和驾驶证的到期日为年限届满日（同月同日），普通护照的到期日为年限届满日前一日。出生医学证明和预防接种证按长期保存；学历证、学位证和房产证按长期保存；职业资格证书和自定义证照支持固定日期区间或长期有效。固定日期区间的有效期起始日自动与签发日期一致，可以配置提前提醒天数，关闭证照模块时会撤销该模块的预约通知。
- 支持图片和 PDF 附件，并可标记为正面、反面、内页、扫描件或其他；附件可改名、预览和随备份恢复。
- 证照首页统一使用“证照类型-持有人”作为显示名称，不使用自定义显示名称；默认将持有人遮罩为“••••••”，可通过右上角临时身份认证在当前前台会话中查看，进入后台后自动恢复遮罩。附件展示名允许重复，磁盘文件仍使用独立内部名称，重命名时可分别编辑文件名和扩展名。
- 可以从图片、PDF 或相机照片中框选区域执行中英文 OCR，候选页列出姓名、证件号、日期、签发机关及模板字段，默认全部勾选，可逐项取消后点“应用”，应用时覆盖表单中已填写的对应字段；性别、民族、住址等已有字段会自动填入，识别出的其他“字段：内容”会在确认后自动创建为自定义字段，未点“应用”时识别结果不会写入表单。
- 同一证照可以保留多个版本，并为每个版本标记正常、已过期、已遗失、已换发或已作废；主列表按证照聚合、默认展示到期日最晚的版本，并按显示名称的拼音/字母统一字典序排列；版本列表仍按到期日从晚到早排列，长期有效优先、没有到期日的数据最后。详情页可查看和编辑，新增子证照（版本）入口位于编辑页。
- 列表支持搜索，并按证照类型、有效期状态、证照状态和标签筛选；查看敏感详情、编辑或新增版本需要独立身份验证，新建和删除由页面直接提供。

### 收支账单

- 当前已在 `Config/Shared.xcconfig` 中关闭编译，以下为保留代码的行为说明。
- 账单页顶部分为“记录”和“分析”；分析支持周、月、季、年和自定义时间区间，并按币种独立统计支出、净支出、收入、退款、结余和交易笔数。周/月/季/年支持与上一周期对比，自定义区间不做对比；可通过日期按钮选择周期基准日或自定义起止日期，账单变更会自动刷新，也支持手动和下拉刷新。
- 取消的交易不进入分析；退款从净支出中扣除，“不计收支”只统计笔数，不与其他币种或收支金额混合。
- 支持手工新增、编辑和删除支出、收入、退款与不计收支记录，转账作为交易分类保存；记录包含金额、币种、交易时间、商户、交易对方、商品说明、支付方式、付款账户、分类、状态、标签和备注。
- 支持从照片或图片文件载入付款截图，框选区域后复用 Core Vision OCR 进行中英文准确识别；识别出的金额候选、日期、商户和支付方式必须在确认后才保存，原始图片和整段 OCR 文本不会默认写入 Vault。
- 列表支持搜索以及按收支类型、分类和标签筛选，显示本月人民币支出、收入及退款与结余；不同币种不会被错误相加。列表和任意筛选结果默认显示前 30 条，滑动到底部后每次继续加载 30 条。
- 内置 `com.fjwyz.mytools.bill-exchange` 版本 2 JSON 交换协议，包含来源、账户、交易时间、收支方向、金额币种、平台交易类型与分类、商户/对方及对方账号、商品、渠道、标准状态与平台原始状态、交易号、商户订单号、退款关联和原始字段；导入前提供预览，重复的“来源 + 外部交易号”会更新而不会重复累加；再次导入平台账单只刷新平台字段，保留用户修改的分类、备注并合并标签；导入本机导出的方寸 JSON 按记录 ID 匹配，重复导入不会产生副本。
- 可从“我的 > 设置 > 模块设置 > 收支账单”导出 JSON 账单；支持近一月、近三月、近半年、近一年、全部和自定义日期区间，并可继续按来源、分类和收支方向筛选。
- 可直接导入微信支付 XLSX 和支付宝 GB18030/UTF-8 CSV。解析器自动定位“交易时间”明细表头，只转换表头后的交易记录，姓名、账户、收支汇总、导出说明和提示等顶部内容不会进入账单；微信的“/”和支付宝的“不计收支”统一映射为不计收支，退款、关闭及处理中状态会转换为统一状态，同时保留平台原值；支付宝“交易关闭”的支出如有对应退款，记为已退款，避免重复冲减。导入文件上限 20 MB，XLSX 行列数超出 Excel 上限时停止读取。
- XLSX 使用系统压缩与 XML 能力读取，不增加第三方依赖；支付宝 CSV 支持引号、字段内逗号和换行。OFX、ISO 20022 `camt.053` 及各家银行卡 CSV 可继续作为外部 Adapter 接入，但不作为内部核心格式。

### 体彩开奖

- 当前已在 `Config/Shared.xcconfig` 中关闭编译，以下为保留代码的行为说明。
- 首次打开默认展示英超、西甲、意甲、德甲、法甲和欧冠；右上角可以按中国体育彩票赛事简称或全称添加其他赛事，赛事行支持红色左滑删除。
- 按赛事调用中国体育彩票公开赛果接口：首次分页获取最近 30 天比赛，之后仅刷新最近 3 天和仍未完整开奖的场次，并补齐准确开赛时间及“胜平负、让球、半全场、总进球、比分”五类结果；比赛默认先按开赛时间倒序、同一时间再按官方场次号倒序，长按比赛行可以调整并持久化展示顺序。
- 进入某个赛事的比赛页时会自动强制刷新一次，之后仍按既有的手动刷新和 10:00/22:00 自动刷新策略运行。
- 比赛尚未开奖或官方字段缺失时，比分显示“暂无数据”，各玩法结果显示“暂无”；这表示该场次暂时没有可用数据，并非整个赛事没有数据。获取失败时弹出“暂时无法获取体彩开奖数据：…”说明原因，已缓存的赛果继续显示。首页隐藏体彩模块会停止前台定时检查并取消系统后台刷新。某个赛事获取失败不影响其余赛事；单场补全失败时保留上次已得到的开赛时间与玩法结果，单行字段缺失只跳过该行。赛果独立持久化在 `Application Support/MyTools/sports-lottery-cache-v1.json`，前台在北京时间每天 10:00 和 22:00 检查增量；iOS 进入后台后预约相同时间点附近的系统后台刷新，但实际执行时刻由系统决定。手动刷新可随时强制获取最新数据。
- 赛事列表固定按简称的拼音/字母统一字典序排列；赛事选择和比赛展示顺序偏好只保存在 `UserDefaults`，赛果缓存不进入业务 Vault、加密备份或 CloudKit，但赛事偏好会作为应用设置同步。

## 数据存储与备份

- 银行账户、银行卡、股票、换汇记录、健康档案、医疗机构资料、保密资料、证照（以及启用编译时的账单）统一保存在 App Sandbox 的 `Application Support/MyTools/local-vault.json`。该档案使用 AES-GCM 静态加密（格式 2.1，信封头作为附加认证数据；仍可读取 2.0 旧信封，下次保存时升级），随机 256 位密钥保存在 Keychain（`WhenUnlockedThisDeviceOnly`，仅本机、不可迁移）；旧版明文档案在首次读取后升级为加密格式：先把原文件保存为 `pre-encryption-*.snapshot` 副本，再写入临时文件并解密校验，确认无误后原子替换正式文件，不直接改写正式文件。图片与 PDF 附件仍以未加密文件存放在附件目录，附件加密是后续工作。
- 本地档案读取失败时弹出“本地档案读取失败”，可选择重新读取；某个模块的数据无法解码时，该模块页显示“此模块的数据暂时无法读取”并暂停其编辑和同步，原始资料保留，其他模块照常使用。读取失败不会显示成空列表或“暂无数据”。
- 健康附件、信用卡账单 PDF、保密资料附件和证照附件保存在 Application Support 的附件目录；本地 JSON 只保存附件元数据，备份时会一并打包附件内容。
- 日常档案使用原子写入，并在后台串行保存；App 进入后台时会等待排队中的保存完成。
- 诊断日志按本地日期滚动保留最近 7 天；每天首次写入或导出时清理过期记录，预览不触发全文件裁剪或强制落盘。调试页独立加载事件日志、系统日志和 MetricKit 报告数量；预览最多展示最近 100 条，最新在前，长行截断显示，完整内容通过诊断包导出。清空诊断数据在后台执行，不阻塞界面。
- 系统日志抄本超出 4 MiB 时按完整行保留尾部约 3 MiB。诊断包使用 `event.log`、`system.log` 和 `CallStacks/`；iOS ZIP 声明 UTF-8 文件名。清空后记录后台执行耗时，方便真机核对；后台冷启动不启动前台卡顿监控。
- 系统日志每 30 秒抄写一次，单轮最多 2500 条并按每 250 条分块写盘；条数多或耗时长的轮次记录条数、耗时与内存变化。系统日志达到 4 MiB 后裁至约 3 MiB，启动采集时也检查旧文件，避免持续超限重写。诊断清理并行处理三类产物，某一类失败仍清理其余两类，并明确提示失败；本地压力测试仅使用临时文件，不删除用户诊断记录。
- “我的 > 设置 > 存储与数据”会预览当前已编译且在“首页功能”中可见模块的不适用字段值，确认后可定向清理；清理结果会写回本地 Vault，并在 iCloud 同步已开启时参与下一次 CloudKit 对账。隐藏模块和未编译模块的不透明数据不会被扫描或修改，已经导出的旧备份也不会被改写。
- “我的 > 设置 > 存储与数据 > 本地缓存”可以按功能清理可重新下载的行情图、刷新状态、共享汇率牌价缓存（启用体彩编译时还包括体彩赛果缓存）；该操作只影响本机缓存，不删除业务记录、附件、提醒或 iCloud 数据。股票投资与换汇共用汇率缓存，清理任一项都会使共享牌价下次重新获取。
- 存储页会将本地档案、附件、CloudKit 同步状态、应用缓存和系统 CloudKit 本地缓存分开统计；同步状态、行情/赛果缓存和诊断日志均标记为不参与系统 iCloud 设备备份。系统 CloudKit 缓存由系统管理，仅用于本机同步记录/附件访问，不是应用上传的业务快照。
- “我的 > 设置 > 存储与数据 > 删除功能数据”可以按功能删除该功能的业务记录、附件、提醒状态和专属缓存。删除前通过两层确认，每层等待 10 秒；执行后再保留 10 秒撤回窗口。撤回期内附件不会物理删除，目标模块也暂不参与 CloudKit 对账；窗口结束后才清理附件/缓存并提交删除。开启 iCloud 同步时，最终删除会同步到同一账户的其他设备；已经导出的旧备份不会被修改。
- 可以从“我的”页面导出或导入 `.mytools` 加密备份。备份使用 PBKDF2-HMAC-SHA256 派生 256 位密钥，并使用 AES-GCM 加密；新导出的备份格式版本为 `2.0`：PBKDF2 轮数（60 万）写入信封，信封头作为 AES-GCM 附加认证数据，篡改版本或轮数会导致解密失败；仍可导入 21 万轮的 `1.0` 旧备份。备份同时记录包含的工具模块。
- 当前导出备份只包含已编译且在“首页功能”中可见的业务模块；隐藏模块的数据仍保留在本地，并继续参与 CloudKit 同步，但不会进入这一次备份。导入时也只合并当前可见且已编译的模块；如果需要完整备份隐藏模块，应先在“首页功能”中显示它们后再导出。
- 当前只读取最新的本地容器和备份载荷结构，不再兼容更早的顶层 `VaultData`、旧体检嵌套批次或单选医疗机构字段。
- 备份密码至少 8 位；用户在密码页输入独立的备份密码。App 不保存该密码，丢失后无法解密备份。
- 导入备份按模块整体替换：备份中包含的模块以备份内容为准，该模块在备份之后新增或修改的本机记录会被移除；未包含在备份中的模块保持不变。对应的健康附件、信用卡账单、保密资料附件和证照附件会一并恢复。导入前会把当前加密档案原样保存为 `pre-restore-*.snapshot` 副本；本地档案未能成功读取时拒绝导入，以免覆盖原文件。
- 可在“我的 > 设置 > iCloud 同步”中主动开启 CloudKit 私有数据库同步；该功能默认关闭。银行、银行卡、股票持仓、换汇、健康档案、医疗机构、提醒、保密资料、证照和附件（启用编译时还包括账单）按记录增量同步，多个设备需登录同一 Apple 账户。
- 云端删除只针对本机曾同步过、随后被本机删除的记录；远端变更合并失败的记录标记为待重试，下次同步重新合并，期间既不上传旧内容，也不当作本机删除。单次对账若要删除至少 20 条且超过当前记录 25% 的记录，而这些记录不来自“删除功能数据”或备份导入，会暂停这部分删除并在“iCloud 同步”中显示“已暂停云端删除”，由用户确认后再执行。
- CloudKit 部分失败会逐条记录子错误码与脱敏记录名（仅保留类型与 UUID 前 4 位）；子错误全部属于可自愈类型（如 serverRecordChanged、unknownItem、zoneNotFound）时只记 INFO 并等待引擎自动重试，不在界面提示错误。自动同步不与 `start()` 及手动同步交叠上报状态。
- 当前不提供“重建 iCloud 数据”操作。若 `MyToolsData` 私有数据区在服务器端被删除（例如用户在系统设置中删除了本 App 的 iCloud 数据），下次同步会清空本机的同步令牌和已同步记录状态，再以本机快照重新创建数据区并完整上传；本地 Vault 和附件不会删除。
- 首页模块开关和排序会持久化到本机 `UserDefaults`；开启 iCloud 同步后，它们会作为应用偏好写入 CloudKit 私有数据库，因此重新安装后登录同一 Apple 账户并重新开启同步即可恢复。隐藏模块不会停止业务数据同步，只有“删除功能数据”撤回窗口内会暂时排除目标模块；关闭首页显示也不会因为快照缺失而删除云端历史。银行登录字段模板、各模块标签库、保密字段模板以及页面排序/筛选偏好也会随对应数据同步。
- 删除功能本地数据并完成撤回窗口后，iCloud 同步会对该功能已删除的 CloudKit 记录执行真正删除；本地仍保留轻量 tombstone 处理多设备删除冲突。iCloud 设置中的用量是服务器口径，可能在删除后短时间高于本机，直到历史记录/附件版本完成回收。
- 当前 CloudKit 使用稳定的实体键和单个私有数据区，不会因普通增量同步主动制造重复业务记录。iCloud 用量明显高于本机时，通常来自历史附件版本、已删除记录的服务端延迟回收、旧设备尚未完成删除对账或云端暂存变更；客户端不能直接删除 CloudKit 历史版本，App 也不提供主动重建数据区的入口；历史版本回收由 Apple 服务端处理并可能延迟。
- 编译配置可以让模块参与编译但默认不显示：在 `Config/Shared.xcconfig` 中将对应 `MYTOOLS_HIDE_*` 设为 `MYTOOLS_DEFAULT_HIDDEN_*`。该默认值只用于没有本地显式设置的新安装，已有本地设置和 CloudKit 远端偏好优先。
- 本地档案始终是离线数据源。股票行情、汇率缓存、诊断日志和设备认证状态不会上传；附件使用 `CKAsset`，业务 JSON 写入 CloudKit 的加密字段。启用体彩编译时，体彩开奖内容仍是网络只读缓存，赛事选择和自定义顺序等用户偏好随应用设置同步。关闭同步不会删除本机资料。
- CloudKit 使用记录级增量对账：主线程只采集当前状态，JSON 编码与附件读取在后台完成；连续本地修改先用 2 秒防抖合并为一次差异计算，上传与拉取交给 `CKSyncEngine` 系统调度，只有手动“立即同步”才强制发送；股票报价字段属于设备本地派生数据，报价刷新只写本地档案，不触发全量业务快照；业务记录同步成功后会丢弃同步状态中的重复 payload 和 CloudKit system fields，仅保留摘要、待发送内容和附件元数据。`cloud-sync-state.json` 使用 LZFSE 压缩并排除系统备份，旧版 JSON 状态可自动读取；system fields 只在待上传/重试期间保留，避免大量账单把同步状态膨胀成本地第二份数据库。远端附件在业务记录可用后后台逐个恢复，避免启动时因全量编码或大附件产生卡顿和内存峰值。启动时会先检查构建包的 iCloud 容器 entitlement；没有有效签名能力的 macOS Debug 包（例如未签名构建或 Xcode 测试宿主）自动关闭 CloudKit，绝不创建 `CKContainer`，避免无权限初始化导致启动崩溃；正式 iOS/iPadOS/macOS 签名包仍按 entitlement 启用同步。
- 带业务更新时间的记录按真实 `updatedAt` 判断新旧，不使用设备启动或同步缓存时间抬高版本；升级到同步协调格式 v4 时会清空一次旧协调缓存并先完整拉取 CloudKit，防止久未使用的设备把旧文档重新上传并覆盖其他设备上的更新。
- 同步状态容量准则：已成功同步的活动记录只保留稳定记录键、摘要、版本时间和删除标记；payload 只为待发送/冲突重试记录保留，未编译模块的不透明数据才允许作为恢复所需的离线 payload 留存。数据量增长后本地状态按记录数线性增加轻量元数据，而不会按业务 JSON 大小重复增长；CloudKit 服务端仍需保存完整业务 payload，这是跨设备恢复的必要数据，不应改成一个巨型聚合记录。
- 同步状态的读取、解压和旧格式迁移在 utility 后台任务执行，不能阻塞主线程创建首屏；同步 Worker 创建阶段不得直接读取几十 MB 的状态文件。

## 安全边界

- 本地 JSON 档案（`local-vault.json`）已使用 AES-GCM 静态加密，密钥以 `WhenUnlockedThisDeviceOnly` 保存在 Keychain 且不随备份/迁移转移；系统升级、重新安装构建或锁屏后台启动导致受保护数据暂不可用时，App 保持启动加载状态并在设备解锁、场景激活及短暂退避后自动重试，不会把临时状态误判成档案损坏。加密写入遇到同类临时错误时保留最新待写快照并自动重试，绝不降级为明文。密钥真正丢失时档案不可读，只能通过 `.mytools` 加密备份恢复。图片与 PDF 附件仍以未加密文件单独存放在同一 Application Support 下（iOS 文件使用系统文件保护），附件加密尚未实现。
- App 沙盒隔离和敏感信息界面遮罩不能替代应用层加密；敏感详情使用系统设备身份验证，当前没有应用自有管理员密码或管理员会话。
- 导出备份文件使用用户输入的独立备份密码加密；App 不保存该密码，丢失后无法解密备份。
- CloudKit 同步是可选的数据副本与多设备合并能力，不能替代独立的 `.mytools` 加密备份。切换 Apple 账户，或用户从 iCloud 清除方寸数据时，App 会保留本机资料并自动关闭同步，避免误传到其他账户或重新上传已清除的数据。

## 打开与运行

1. 在 Xcode 中打开 `MyTools.xcodeproj`。
2. 选择 Scheme `MyTools`。
3. 本仓库默认配置使用作者的 Bundle Identifier，Xcode Cloud 可直接据此归档；其他开发者在真机安装前，应把 `Config/Signing.local.xcconfig.example` 复制为 `Config/Signing.local.xcconfig`，填写自己的 `DEVELOPMENT_TEAM` 和唯一 Bundle Identifier。
4. 在 Apple Developer 与 Xcode 的 Signing & Capabilities 中为这个 Bundle Identifier 启用 iCloud/CloudKit、Push Notifications 和 Background Modes，并创建 `iCloud.<你的 Bundle Identifier>` 容器。`MyToolsRelease.entitlements` 会按构建时的 Bundle Identifier 引用该容器。
5. `Signing.local.xcconfig` 不会提交到 Git。仓库中的 `Shared.xcconfig` 保留本 App 的默认 Bundle Identifier，其他开发者使用本地配置覆盖它。注意 `project.pbxproj` 的 target 级构建设置仍写有作者的 `DEVELOPMENT_TEAM`（6Y8D******），优先级高于 xcconfig，其他开发者需在 Xcode 的 Signing & Capabilities 中改成自己的 Team；签名证书由 Xcode Cloud 或本机签名设置提供。
6. `Config/Shared.xcconfig` 中的 `MYTOOLS_ENABLE_*` 行是业务模块唯一编译开关，注释某一行即可构建不含该模块代码、页面、服务注册、备份和 CloudKit 参与逻辑的产品变体；`MYTOOLS_COMPILED_FEATURES` 由这些开关汇总生成，不要在其他构建设置中维护第二份清单。需要“编译但默认隐藏”时，配置对应的 `MYTOOLS_HIDE_* = MYTOOLS_DEFAULT_HIDDEN_*` 行；`MYTOOLS_DEFAULT_HIDDEN_FEATURES` 会自动加入 App 和测试 Target 的 Swift 编译条件。
7. 选择 iPhone、iPad 或 My Mac 后运行。

首次开启同步后，用开发签名运行 App 并新增或修改一条记录，确认 CloudKit Dashboard 的 Development 环境出现 `MyToolsEntity` 记录类型和 `MyToolsData` 自定义 Zone。上传 TestFlight 或 App Store 前，必须在 CloudKit Dashboard 执行 **Deploy Schema Changes to Production**；否则开发环境正常而正式版本无法读写。

Xcode Cloud 上传 TestFlight 构建时，会读取与 `MyTools.xcodeproj` 同级的 `TestFlight/WhatToTest.zh-Hans.txt`，自动填写简体中文“测试内容”。该文件采用静态维护方式，每次触发正式 TestFlight 构建前应先更新并提交；它不会修改已经上传的旧构建，也不是 App Store 版本页的“此版本中的新内容”。

首次使用建议：先从“金融账户”“股票投资”和“健康档案”录入数据，最后导出一份 `.mytools` 备份。

## GitHub 仓库文件

仓库需要保留源码、资源、`Info.plist`、`MyTools.xcodeproj/project.pbxproj`、共享 Scheme、工作区基础文件以及 `Config/Shared.xcconfig`。这些文件共同描述 Target、编译源文件、资源、系统权限和构建设置，仅上传 Swift 文件无法直接还原可编译工程。

## 架构边界

- `Core` 保存不归属于单个可关闭工具模块的基础能力；基础能力不能依赖某个业务模块的可见状态。
- `Features/*/Domain` 只保存业务模块的 Codable 数据和可确定计算，不直接访问文件、网络或 SwiftUI 状态。
- `AppStore` 是主线程上的应用状态协调器，负责把编辑结果交给持久化、附件和行情服务；页面不直接写本地文件。
- `SecureStore` 负责本地 JSON 的读写，`VaultPersistenceCoordinator` 在串行后台队列合并写入，并把失败错误码回传给应用状态。
- `AttachmentStore` 负责单个附件的文件生命周期；备份处理器负责健康、金融、保密资料和证照的附件映射，四个模块共用同一套文件安全属性和预览包装器。
- `AuthManager` 只负责敏感信息查看所需的设备身份验证，不维护应用自有管理员会话。
- 股票和换汇模块都可以使用基础牌价能力；只有两个模块均隐藏或未编译时才停止牌价刷新。首页可见性分别控制各自页面、提醒和模块专属后台任务；备份范围另由备份参与声明及当前可见性共同决定，隐藏模块当前不进入加密备份。
- 即时报价、历史行情和牌价服务分别承担网络请求与解析；看盘原始时序写入独立离线缓存，不进入 `AppStore` 的业务 Vault 或加密备份。

历史参考汇率由 `Core/Currency/HistoricalExchangeRateService.swift` 提供：Frankfurter v1 日线以 CNY 为基准，牌价页默认回补近一年，按 UTC 自然月缓存于 Caches/MyTools/ReferenceExchangeRates，缓存 schema 1，排除备份及 CloudKit。未发布日留空；澳门元等不支持币种明确提示；不与中行现汇买卖价混合。股票或换汇模块清理共享缓存时同时清理参考历史。缓存损坏或未来版本保留原文件并停止回补，网络失败保留已加载曲线。

旧银行档案备份的离线转换工具见 [scripts/finance/README.md](scripts/finance/README.md)；转换时必须生成新文件，禁止覆盖原备份。

金融账户首页的银行、券商和支付机构均支持左滑删除并确认；添加菜单只提供这三类机构，既有“其他”档案仍可查看。股票持仓总览常驻展开，点击市值行或行内走势图标进入持仓总价值走势；看盘列表末尾可展开已归档股票，左滑可取消归档。

证照详情的信息字段复用 Core 的单行／多行自适应行，长内容自动换行；顶部概览右侧锁按钮经系统身份验证解锁私密信息，再次点击可锁定，工具栏仅保留编辑。编辑已有证照时可从“子证照”区域新增同组版本，沿用既有版本模型和附件编辑会话。

保密资料列表固定复用 Core `AppAlphabeticalSort`，按名称拼音／字母升序、数字自然顺序排列，同名以条目 ID 稳定排序，不提供工具栏排序开关；旧排序偏好不再影响列表。

看盘页自动刷新覆盖当前市场筛选中的全部未归档股票，“全部”模式由协调器逐市场判断交易时段；盘前盘后的价格、涨跌和迷你图同时更新，迟到的旧缓存读取不会覆盖新分时结果。
