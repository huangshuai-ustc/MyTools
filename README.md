# 方寸（Fangcun）

“方寸”（英文名 `Fangcun`）是一个使用 SwiftUI 编写的本地优先多平台应用，界面语言为中文。应用把金融账户、股票、换汇、健康资料、美食地点、保密资料、证照资料和收支账单集中保存在本机，并提供独立的体彩赛果查询工具，适合个人长期记录、查询和备份。

隐私政策：<https://huangshuai-ustc.github.io/MyTools/privacy.html>

当前包含九个工具模块：

- **金融账户**：银行账户、子账户、银行卡和信用卡账单
- **股票投资**：A 股、港股、美股的持仓、交易和分红
- **换汇记录**：换汇流水、中国银行牌价和人民币损耗
- **健康档案**：就诊、复诊、药房购药、体检、费用和附件
- **美食地图**：吃过或想吃的美食、店铺、地点、图片和来源
- **保密资料**：账号密码、邮箱授权、服务 Token、备份密钥和软件授权
- **证照**：身份证、护照、港澳通行证、驾驶证、学历学位证、房产证、出生医学证明、预防接种证和职业资格证书等重要证照
- **账单**：手工记账、图片 OCR、交换文件导入和付款明细管理
- **体彩开奖**：按赛事查看比赛、时间和竞彩足球开奖结果

## 平台与工程

- iOS / iPadOS 26.0 及以上
- macOS 26.0 及以上
- Xcode 26.0 及以上
- Swift 6.0、SwiftUI 多平台工程
- 默认 Bundle Identifier：`com.fjwyz.PersonalToolBox`，可以通过本地签名配置覆盖
- 工程文件：`MyTools.xcodeproj`
- Scheme：`MyTools`
- App 中文显示名称：`方寸`
- App 英文显示名称：`Fangcun`
- 不依赖第三方 Swift Package

源码目录、Swift 模块、Target、Scheme、本地数据目录和备份扩展名统一使用内部名称 `MyTools`，以保持源码与既有数据兼容；当前 App 对外显示名称仍为“方寸”，英文系统显示为 `Fangcun`。版本信息以工程 `Info.plist` 和应用“我的 > 关于”页面为准。

## 功能

### 工具首页

- 按模块进入“金融账户”“股票投资”“换汇记录”“健康档案”“美食地图”“保密资料”“证照”“账单”和“体彩开奖”。
- 在“我的 > 首页功能”中显示或隐藏模块，并拖动调整模块顺序。
- 首页顺序与设置页保持一致；关闭的模块不会出现在工具首页。

### 标签规范

- 健康档案、美食地图、保密资料、证照和账单统一使用标签能力：输入时以中文逗号 `，` 分隔，保存时自动去除空白、去重并兼容旧版逗号/顿号分隔数据。
- 标签在列表、详情和筛选入口中以灰色背景胶囊显示，不再用一段顿号连接的普通文本；选中的筛选标签使用强调色胶囊。
- 每个功能独立持久化已使用过的标签。编辑记录时会显示该功能的历史标签建议，点击即可复用；删除记录不会清空标签建议库。
- 上述功能的列表都支持标签搜索；健康档案、美食地图、保密资料、证照和账单均可按标签筛选。

### 金融账户

- 支持境内银行和境外银行，首页可按“全部”“境内”“境外”筛选。
- 银行档案保存银行、支行、状态、开户时间、备注以及境外银行的 SWIFT、IBAN、地址和汇款资料。
- 分行/网点名称在详情中作为地图链接显示，已有坐标可直接打开地图导航；没有坐标时显示黄色警告并以天安门为默认选点，可搜索或手动修改后保存。网络银行可单独标记为“无实体网点”，不显示缺失位置警告。
- 美食地图和银行网点共用 Core 层 `MapLocationPickerView`、`MapLocationSearchService` 和 `MapLocationSearchResultRow`：统一处理定位权限、地图展示、搜索取消、候选结果、国际地址解析、反向地理编码、手动点选、整行点击、蓝色选中标记和保存/取消；两个模块只保留各自的业务结果转换。
- 支持境内和境外子账户；每个子账户单独保存类型、名称、账号、币种和“正常/异常/销户”状态。
- 境内子账户额外支持支票账户；银行登录信息支持逐项编辑、删除、显隐，境内与境外分别维护可复用的登录字段模板。
- 支持借记卡和信用卡；银行卡可保存卡号、CVV、有效期、持卡人、卡组织、币种、状态和开卡时间。
- 信用卡可添加多份 PDF 账单，保存账单日期和备注；账单附件可以随加密备份导出和恢复。
- 首页默认隐藏停用银行；银行详情默认隐藏已销户银行卡和子账户。隐藏项目可以临时展开，不会删除数据，境内境外使用相同规则。
- 首页统计只计算当前可见的银行、未销户子账户和未销户银行卡，并显示银行、子账户、借记卡和信用卡数量。
- 支持按地区筛选、搜索银行/支行/账户类型/账号/币种/卡种/持卡人，以及按名称、开户时间、地区和卡片类别排序。
- 普通模式可以查看档案详情；完整卡号、CVV、有效期、登录密码、敏感附加字段和信用卡账单需要单独验证身份后查看。
- 银行、银行卡和子账户详情中的已填写文本支持长按复制，并显示复制提示。

### 股票投资

- 支持 A 股、港股和美股；每只股票保存市场、代码、自定义名称、买入/卖出流水和分红流水。
- 新增股票支持按中文名称、英文名称或股票代码模糊搜索，候选结果按当前市场和交易所筛选，并标识交易所/证券类型；同一代码的多源结果会合并，美股使用原生正式名称和规范代码回填，中文简称优先使用券商返回的短名称，不再把搜索关键字当作简称。候选行将规范代码放在正式名称右侧的标签中，第二行显示中文简称和交易所/证券类型，减少候选高度。点击候选时只自动回填代码，股票名称仍由用户自行填写，不会把候选的正式名称写入自定义名称。候选排序依次考虑代码/正式名称精确匹配、中文名称完整/后缀/前缀/包含匹配、普通股优先于 ETF、主板交易所优先于 OTC、数据源相关顺序和稳定的热门代码兜底；例如“可乐”按 `KO`、`PEP`、`COKE`、`CCEP`、`KOF`、`CCOJY` 展示，“可口可乐”和“可口”也会把 `KO` 主股票置前。搜索服务没有公开统一的实时热度分数，因此不按实时成交量改变顺序；未找到结果时会明确提示，也可以继续手工输入代码保存。
- 新增股票默认记录首次买入日期、股数、价格和交易费用；打开“仅看盘”后可只保存股票代码和行情信息，详情页可以继续维护买入、卖出和分红。
- 卖出、编辑或删除交易时按交易日期校验任意时点的持仓不能小于零。当前持仓、持仓成本、持仓盈亏、已变现利润和总盈亏均由流水自动计算。
- 分红记录支持到账日期、分红股数、每股分红、预扣税、其他费用和备注，净分红自动计入总盈亏。
- 市场筛选入口会根据实际买入记录动态显示：没有某个市场的买入记录时不显示该市场，新增买入记录后自动出现；“全部”只包含有买入记录的股票。
- A 股、港股、美股分别使用 CNY、HKD、USD 汇总；“全部”视图可按中国银行港币和美元现汇买入价折算人民币。
- 市场概览显示持仓成本、持仓盈亏、已变现利润和资产占比；股票详情仍显示当前市值，缺少行情或汇率时显示“待同步”，不会按零估值。
- 股票页面打开时只在活跃交易时段自动刷新对应行情：美股盘前刷新盘前、盘中刷新盘中行情，盘后只刷新盘后分时；A 股和港股只在正式交易时段刷新。K 线在正式交易时段内与盘中行情保持同一自动刷新节奏，分时每 30 秒轮询，5 日和 K 线每 60 秒轮询；各市场正式交易时段结束后，后台执行一次完整行情收口，刷新分时、5 日分钟和日线基础序列，重新计算全部技术指标，并由日线源更新周/月/季/年 K 线，失败后每 5 分钟允许重试。盘前、盘后不会触发 K 线基础序列刷新，休市时除该完整行情收口外只读取缓存，手动刷新可以忽略交易时段并强制请求。行情失败时保留最后一次成功的价格和更新时间；看盘页的“当期数据”独立使用当前或最近有效交易日的分钟分时汇总开盘、最高、最低、收盘/最新和成交量，不随 K 线范围切换而重新请求。
- 每条股票向右滑动可以直接进入看盘页，不要求管理员权限；行情周期采用市场常见的“分时、5 日、日K、周K、月K、季K、年K”七档。分时和 5 日均使用 1 分钟线，分别默认定位最近交易日和最近五个交易日，保持固定的近期窗口，不提供平移和缩放；日K、周K、月K、季K、年K使用各自的长周期行情序列，所有周期首次进入统一默认选择“盘中”，用户切换均线、布林等图层后在内部加载和周期切换时保持选择，默认窗口分别约为近 3 个月、近 2 年、近 5 年、近 10 年和成立以来；新上市股票按实际可用的 K 线柱绘制，即使只有一两根历史柱也不会被误判为无数据，底层保留更完整的历史序列，可通过横向滑动查看更早内容、双指缩放查看更宽或更窄的时间窗口；所有长周期行情图类型均支持单击选最近行情柱、普通单指拖动连续吸附选点、长按后单指拖动平移时间窗口和双指缩放。只有美股分时图提供连续的盘前和盘后图表模式，分别用橙色和蓝色曲线展示；A 股开盘/收盘集合竞价、港股开市前/收市竞价属于竞价阶段，不作为连续盘前/盘后价格线，因此不在图表模式中显示。美股盘前时段不能与盘中拼接，盘中时段允许盘前+盘中但不允许盘后，盘后及休市时段允许盘前+盘中+盘后，盘前与盘后始终必须由盘中连接；行情图会用不同颜色标注买入、卖出日期及成交价，并可展开为横屏图表；分时盘中图的交易标记以交易价格为纵坐标，在同一交易日内选择价格最接近且同价优先更早的行情柱，横坐标与当前可见盘中保持一致；成交量摘要明确标注买入、卖出或持平，均线绘制在布林带区域之上；技术指标同时展示 RSI14 和 RSI30，分时与 5 日图的均线、布林和 MACD 使用跨交易日的 1 分钟历史预热但只投影当前展示区间，分时 RSI 使用分钟级历史，5 日及以上 RSI 使用交易日收盘序列，日线参考序列与分钟/周/月可见图表分开缓存；数据源未返回美股扩展时段行情时明确显示暂无数据，均线、布林、MACD 和 RSI 只基于正式交易序列计算；盘后当期数据取最近有效的正式交易周期；分时页在美股盘前、盘中和盘后三个活跃区间内每 30 秒更新一次，休市时不再持续实时更新。
- 行情图切换时间区间或手动刷新时，如果目标区间需要后台补充数据，会暂时保留已有图表并加半透明加载蒙版；图表区右上角和蒙版中显示转圈进度，明确提示正在更新的区间。自动轮询刷新仍保持静默，不遮挡当前图表。
- 分时和 5 日共用当前行情源返回的盘中分钟原始序列，显示粒度为 `max(1 分钟, 行情源实际间隔)`；日K是唯一的日线原始序列，周K、月K、季K、年K按交易所市场时区本地聚合并作为可重建派生缓存保存，MA、布林、MACD、RSI 也在原始数据落盘时计算并缓存，加载图表时直接读取；成交量保留在 OHLCV 原始柱中并按周期求和；数据源没有成交的分钟不会人为补造价格柱。
- 行情服务使用公开市场接口，并按市场提供批量请求、时间校验和缺失数据兜底；原始时序行情会增量保存在本地离线文件中，但不写入业务档案或加密备份。公开行情可能延迟或暂时不可用，应以交易所和券商数据为准。
- 支持按名称或最早买入时间排序；“我的 > 设置”可以分别设置 A 股、港股和美股的涨跌颜色规则。
- 股票持仓行使用两行三列指标：持仓、成本、涨跌 / 市值、盈亏、盈率；股数按整数千分位显示，持仓数量后会按当前市场筛选范围追加该股票的持仓成本占比（英文括号），全部市场混合时按已同步的人民币现汇买入价折算；金额和百分比仅在展示边界保留两位，成本、盈亏及盈率计算继续使用未截断的十进制 `Decimal`。
- 长周期 K 线优先使用成立以来的年线历史序列作为可靠边界，没有年线时再回退到月线和日线；周线、月线、季线和年线会自动裁剪到实际成立时间，不会显示早于成立以来的数据。
- 股票首页按当前交易流水分为“当前持仓”和“看盘”：当前持仓只由 `currentShares > 0` 决定；买入后清仓的股票保留原有交易和分红历史，并继续显示在看盘中。对已经没有持仓、也不想继续看盘但需要保留历史的股票，可以左滑使用“存档”；原有“删除”按钮仍保留在最右侧。存档只隐藏列表和行情刷新，不删除记录，也不改变总盈亏、已实现盈亏或备份/CloudKit 同步。工具栏可以显示“历史股票”并恢复看盘。
- “我的 > 设置 > 通知与提醒”中的股票提醒选择器按 A 股、港股和美股分组，便于从较长的股票列表中查找。

### 换汇记录

- 保存换汇日期、卖出币种、买入币种、价格口径、卖出金额、实际买入金额和手续费；日期按当天保存，记录按日期倒序排列。
- 支持两种价格口径：`100 买入币种 = ? 卖出币种`，或 `100 卖出币种 = ? 买入币种`。
- 理论买入金额由价格和卖出金额计算，实际买入金额由用户填写；两者差额用于分析汇率损耗。手续费按卖出币种额外支付。
- 当前支持人民币、港币、美元、加拿大元、瑞士法郎、欧元、英镑、日元、新西兰元、新加坡元、泰国铢和澳大利亚元；金融账户和换汇记录共用币种定义。
- 每笔记录按当前中国银行现汇买入价折算交易前成本和交易后人民币价值，计算人民币损耗或盈利；牌价缺失时显示“待同步”。
- 换汇概览显示记录数、涉及币种和累计结果；亏损显示“人民币总损耗”，盈利显示“人民币总盈利”。
- 支持按“全部/买/卖/换”筛选、按年份筛选、按相关币种和组合币种筛选、搜索币种名称或代码，并按月份分组。
- 提供中国银行结售汇牌价页和双向换算器，可在内置币种之间换算；牌价缓存供股票投资和换汇记录共用。
- 支持新增、编辑和侧滑删除，记录随本地档案和加密备份保存。

### 健康档案

- 健康记录支持门诊、急诊、住院、药房购药和体检。
- 就诊记录保存日期、医院、医院级别/等次/性质、科室、医生、主诉、诊断、治疗建议、费用、支付方式、标签、备注和附件；医院以外的机构不设置医院级别、等次和性质。
- 医疗机构资料库统一收录医院、药房和体检机构；编辑机构或新增记录时可以选择机构类别，记录中选择或输入已有名称时会按类别筛选并自动回填医院分类。
- 药房购药记录保存购药日期、药房、药品、购药原因、费用、支付方式、标签、备注和附件；可以作为独立记录，也可以关联到某次就诊。
- 任意门诊、急诊或住院详情可以新增多条关联复诊和关联药房购药；关联记录保留原就诊上下文，并按实际日期计入费用统计。
- 体检按轮次保存：第一次体检就是原始体检记录，后续检查通过关联体检记录添加，既可以只有一轮，也可以有多轮；每一轮都使用统一的健康记录编辑器，保存体检日期、机构、完成项目、检查结果、健康建议、关注项和附件。
- 体检“查出的问题”支持 Markdown 文本，并兼容常用的行内数学写法，例如 `$24.9kg/m^2$` 会显示为 `24.9kg/m²`。
- 费用由费用项目自动合计；支持自费、医保、医保后自费三种支付方式，金额输入支持数字和 `+ - × ÷` 及括号。
- 医疗档案首页显示年度总费用、医保支付、自费费用、机构数量和就诊/体检次数；支持切换年份。
- 支持搜索医疗机构、药房、体检机构、套餐、检查项目、关注项、科室、医生、诊断、费用项目、附件和标签，也可以按标签筛选。
- 支持照片、图片和 PDF 附件，并可分类为发票、病历、检验报告、体检报告、CT、MRI、X 光、化验单、扫描件或其他。
- iOS 使用 Quick Look 预览附件，macOS 使用系统默认查看器打开。健康详情中的文字支持长按复制。
- 首页按原始就诊事件展示复诊和关联购药数量；进入详情后查看完整关联记录。新增、编辑和删除需要管理员模式。

### 美食地图

- 记录吃过或想吃的美食；每条记录可以保存食物名称、店名、中国省市及区县/街道/乡镇等下级行政区、详细地址、地图坐标、吃过日期、标签和备注，国外地点可以不填写中国行政区。
- 支持最多 10 张图片，以及可选的信息来源名称和链接；列表可搜索，并按状态或自定义标签筛选。
- 地图位置可以按店名或地址搜索，也可以直接在地图上点选；搜索候选会在右侧用蓝色对号标记当前选中地点，选点后自动回填详细地址和行政区。新增记录进入选点页时会申请定位权限并优先展示附近区域；详情页以地图卡片显示保存的位置。
- “查看全部标记”集中展示所有已定位地点，支持选中标记后查看详情或跳转 Apple 地图；设备安装对应 App 时，也可选择高德、百度、腾讯或 Google 地图导航。
- 浏览记录、查看总地图和发起导航不要求管理员权限；新增、编辑和删除沿用统一的管理员模式。

### 管理员与敏感信息

- 首次使用时设置至少 8 位管理员密码。
- 可使用管理员密码、Face ID、Touch ID 或设备密码进入管理员模式；“我的 > 设置 > 管理员模式”可选择认证有效期（15 分钟、30 分钟、1 小时、2 小时、4 小时、自定义分钟或永久）以及“进入后台锁定”。默认是“永久 + 进入后台锁定”，保持原有行为；会话策略保存在本机，不上传管理员会话状态。
- 管理员模式统一显示状态标识，并负责新增、编辑和删除金融档案、股票、换汇记录、健康档案、医疗机构资料、美食记录、保密资料、证照和账单；备份导入导出也要求管理员权限。
- 查看敏感信息使用独立的身份验证入口，不会因此进入管理员编辑模式；认证通过后只在当前详情页临时显示。

### 保密资料

- 资料按条目管理；每个条目包含分类、用途（个人/工作）、标签、备注和多个字段，首页与详情会以用途和标签胶囊展示分类信息。
- 内置登录凭据、邮箱账户、服务令牌、备份与恢复、软件授权和其他六类模板；登录凭据默认包含 URL、用户名和密码。
- 字段模板编辑器只显示字段名称输入和字段类型选择（文本、网址、日期）；已有模板字段右滑可显示/隐藏内容或编辑名称，左滑删除字段，长按可拖动调整顺序，不显示常驻拖动柄。详情页始终按当前分类模板计算显示状态，模板修改会同时作用于已有条目和新条目。
- 字段编辑采用左侧字段名、右侧内容的紧凑布局，输入内容出现换行时自动切换为多行文本；字段名固定为模板名称，需从右滑操作进入“编辑名称”或切换内容显隐，字段内容默认遮罩。新增条目会使用当前分类模板初始化字段，切换分类时会立即替换为目标分类的模板字段。
- 管理员可从保密资料首页导入 Apple 密码 App 导出的 CSV；`.numbers` 示例需要先在 Numbers 中导出 CSV。导入会先预览条目，并自动跳过重复登录凭据。
- 保密资料默认锁定，查看需要单独验证身份；新增、编辑和删除需要管理员模式。
- 敏感字段默认遮罩，验证后显示明文；字段内容统一使用长按复制，应用不设置剪贴板过期时间，也不会主动清除复制内容。

### 外部数据导入入口规范

- 外部数据导入不设置长期显示的独立按钮，避免低频操作占用首页和工具栏空间。
- 需要同时支持“新建”和“导入”的模块，将导入作为右上角添加按钮的长按操作；短按添加按钮保持原有的新建行为。
- 长按后先显示“从文件导入”入口，再通过二级菜单选择具体来源，例如账单文件、图片识别或 Apple 密码 CSV。
- 新增其他外部数据导入功能时沿用同样的入口层级，不在列表分类区域或右上角额外放置常驻导入按钮。

### 证照

- 内置身份证、护照、港澳通行证、驾驶证、学历证、学位证、房产证、出生医学证明、预防接种证、职业资格证书和自定义类型；可保存证照名称、持有人、号码、签发机关、必填签发日期、标签、备注及模板字段。出生医学证明记录新生儿与父母、出生信息和签发机构；预防接种证记录受种者、监护人、接种单位和接种记录；职业资格证书记录职业/工种、资格类别与等级、从业范围及注册或复审信息。出生日期不属于通用基本信息，有需要时作为自定义字段记录；旧版固定出生日期可在存储清理中无损迁移为自定义字段。
- 证照“其他信息”采用与保密资料一致的字段编辑体验：字段名、输入形式（文本/网址/日期）和查看时隐藏内容均可配置；单行/多行不设独立选项，字段值包含换行时自动使用多行布局，否则统一使用标准单行行高。字段和模板字段支持右滑显隐/改名、左滑删除和长按拖动排序。每种证照类型都有独立字段模板，模板修改会同步已有字段的显隐设置，新建证照按当前模板生成空白字段；模板随本地档案、加密备份和 iCloud 同步保存。
- 所有证照必须填写签发日期。身份证可选择五年、十年、二十年或长期有效；护照和港澳通行证按五年或十年期限记录；驾驶证按六年、十年或长期有效记录。固定期限均从签发日期计算：身份证、港澳通行证和驾驶证的到期日为年限届满日（同月同日），普通护照的到期日为年限届满日前一日。出生医学证明和预防接种证按长期保存；学历证、学位证和房产证按长期保存；职业资格证书和自定义证照支持固定日期区间或长期有效。固定日期区间的有效期起始日自动与签发日期一致，可以配置提前提醒天数，关闭证照模块时会撤销该模块的预约通知。
- 支持图片和 PDF 附件，并可标记为正面、反面、照片页、签证页、扫描件或其他；附件可改名、预览和随备份恢复。
- 证照首页统一使用“证照类型-持有人”作为显示名称，不再使用自定义显示名称；附件展示名允许重复，磁盘文件仍使用独立内部名称，重命名时可分别编辑文件名和扩展名。
- 可以从图片、PDF 或相机照片中框选区域执行中英文 OCR，再逐项确认姓名、证件号、日期、签发机关及模板字段候选；性别、民族、住址等已有字段会自动填入，识别出的其他“字段：内容”会在确认后自动创建为自定义字段，识别结果不会未经确认直接覆盖表单。
- 同一证照可以保留多个版本，并为每个版本标记正常、已过期、已遗失、已换发或已作废；主列表按证照聚合并默认展示到期日最晚的版本，版本列表同样按到期日从晚到早排列，长期有效优先、没有到期日的数据最后。详情页可查看、编辑和新增版本。
- 列表支持搜索，并按证照类型、有效期状态、证照状态和标签筛选；查看敏感详情需要独立身份验证，新增、编辑和删除需要管理员模式。

### 收支账单

- 账单页顶部分为“记录”和“分析”；分析支持周、月、季、年和自定义时间区间，并按币种独立统计支出、净支出、收入、退款、结余和交易笔数。周/月/季/年支持与上一周期对比，自定义区间不做对比；可通过日期按钮选择周期基准日或自定义起止日期，账单变更会自动刷新，也支持手动和下拉刷新。
- 取消的交易不进入分析；退款从净支出中扣除，“不计收支”只统计笔数，不与其他币种或收支金额混合。
- 支持手工新增、编辑和删除支出、收入、退款与不计收支记录，转账作为交易分类保存；记录包含金额、币种、交易时间、商户、交易对方、商品说明、支付方式、付款账户、分类、状态、标签和备注。
- 支持从照片或图片文件载入付款截图，框选区域后复用 Core Vision OCR 进行中英文准确识别；识别出的金额候选、日期、商户和支付方式必须在确认后才保存，原始图片和整段 OCR 文本不会默认写入 Vault。
- 列表支持搜索以及按收支类型、分类和标签筛选，显示本月人民币支出、收入及退款与结余；不同币种不会被错误相加。列表和任意筛选结果默认显示前 30 条，滑动到底部后每次继续加载 30 条。
- 内置 `com.fjwyz.mytools.bill-exchange` 版本 2 JSON 交换协议，包含来源、账户、交易时间、收支方向、金额币种、平台交易类型与分类、商户/对方及对方账号、商品、渠道、标准状态与平台原始状态、交易号、商户订单号、退款关联和原始字段；导入前提供预览，重复的“来源 + 外部交易号”会更新而不会重复累加。
- 管理员可从“我的 > 设置 > 模块设置 > 收支账单”导出 JSON 账单；支持近一月、近三月、近半年、近一年、全部和自定义日期区间，并可继续按来源、分类和收支方向筛选。
- 可直接导入微信支付 XLSX 和支付宝 GB18030/UTF-8 CSV。解析器自动定位“交易时间”明细表头，只转换表头后的交易记录，姓名、账户、收支汇总、导出说明和提示等顶部内容不会进入账单；微信的“/”和支付宝的“不计收支”统一映射为不计收支，退款、关闭及处理中状态会转换为统一状态，同时保留平台原值。
- XLSX 使用系统压缩与 XML 能力读取，不增加第三方依赖；支付宝 CSV 支持引号、字段内逗号和换行。OFX、ISO 20022 `camt.053` 及各家银行卡 CSV 可继续作为外部 Adapter 接入，但不作为内部核心格式。

### 体彩开奖

- 首次打开默认展示英超、西甲、意甲、德甲、法甲和欧冠；进入管理员（编辑）模式后，右上角可以按中国体育彩票赛事简称或全称添加其他赛事，赛事行支持红色左滑删除。
- 所有模块的左滑删除和右滑操作统一使用 `Core/UI/ListViewModifiers.swift` 中的 `AppSwipeActions` 配置；删除动作统一显示为红色“删除”，仅在管理员（编辑）模式下对记录提供左滑删除，主要操作和辅助操作的颜色及是否允许全滑由公共 modifier 统一控制，各模块不得直接写 `.swipeActions`。
- 展示文字统一使用 `Core/UI/ListViewModifiers.swift` 中的 `.appFont()` 语义字体：iOS/iPadOS 保持系统原生字体样式和 Dynamic Type，macOS 按“外观与文字”中的用户字号统一缩放显式标题、正文、说明、等宽数字以及未单独指定样式的系统控件；列表行高度和单一导航标题同步适配字号，避免同页混用两套字号或标题重复。
- 按赛事调用中国体育彩票公开赛果接口：首次分页获取最近 30 天比赛，之后仅刷新最近 3 天和仍未完整开奖的场次，并补齐准确开赛时间及“胜平负、让球、半全场、总进球、比分”五类结果；比赛默认先按开赛时间倒序、同一时间再按官方场次号倒序，长按比赛行可以调整并持久化展示顺序。
- 进入某个赛事的比赛页时会自动强制刷新一次，之后仍按既有的手动刷新和 10:00/22:00 自动刷新策略运行。
- 比赛尚未开奖或官方字段缺失时显示“暂无数据”。赛果独立持久化在 `Application Support/MyTools/sports-lottery-cache-v1.json`，前台在北京时间每天 10:00 和 22:00 检查增量；iOS 进入后台后预约相同时间点附近的系统后台刷新，但实际执行时刻由系统决定。手动刷新可随时强制获取最新数据。
- 赛事列表和比赛展示顺序偏好只保存在 `UserDefaults`；赛果缓存不进入业务 Vault、加密备份或 CloudKit，但赛事偏好会作为应用设置同步。

## 数据存储与备份

- 银行账户、银行卡、股票、换汇记录、健康档案、医疗机构资料、美食记录、保密资料、证照和账单统一保存在 App Sandbox 的 `Application Support/MyTools/local-vault.json`。该档案使用 AES-GCM 静态加密（格式 2.0），随机 256 位密钥保存在 Keychain（`WhenUnlockedThisDeviceOnly`，仅本机、不可迁移）；旧版明文档案在首次读取后立即原地升级为加密格式。图片与 PDF 附件仍以未加密文件存放在附件目录，附件加密是后续工作。
- 健康附件、信用卡账单 PDF、美食图片、保密资料附件和证照附件保存在 Application Support 的附件目录；本地 JSON 只保存附件元数据，备份时会一并打包附件内容。
- 日常档案使用原子写入，并在后台串行保存；App 进入后台时会等待排队中的保存完成。
- 诊断日志按本地日期保留今天和昨天；每天首次写入、查看或导出诊断日志时自动清理 T-2 及更早记录。
- “我的 > 设置 > 存储与数据”会预览当前已编译且在“首页功能”中可见模块的不适用字段值，管理员确认后可定向清理；清理结果会写回本地 Vault，并在 iCloud 同步已开启时参与下一次 CloudKit 对账。隐藏模块和未编译模块的不透明数据不会被扫描或修改，已经导出的旧备份也不会被改写。
- “我的 > 设置 > 存储与数据 > 本地缓存”可以按功能清理可重新下载的行情图、刷新状态、共享汇率牌价和体彩赛果缓存；该操作只影响本机缓存，不删除业务记录、附件、提醒或 iCloud 数据。股票投资与换汇共用汇率缓存，清理任一项都会使共享牌价下次重新获取。
- 存储页会将本地档案、附件、CloudKit 同步状态、应用缓存和系统 CloudKit 本地缓存分开统计；同步状态、行情/赛果缓存和诊断日志均标记为不参与系统 iCloud 设备备份。系统 CloudKit 缓存由系统管理，仅用于本机同步记录/附件访问，不是应用上传的业务快照。
- “我的 > 设置 > 存储与数据 > 删除功能数据”可以按功能删除该功能的业务记录、附件、提醒状态和专属缓存。删除前必须通过两层确认，每层等待 10 秒；执行后再保留 10 秒撤回窗口。撤回期内附件不会物理删除，目标模块也暂不参与 CloudKit 对账；窗口结束后才清理附件/缓存并提交删除。开启 iCloud 同步时，最终删除会同步到同一账户的其他设备；已经导出的旧备份不会被修改。
- 管理员可以从“我的”页面导出或导入 `.mytools` 加密备份。备份使用 PBKDF2-HMAC-SHA256 派生 256 位密钥，并使用 AES-GCM 加密；当前唯一支持的备份格式版本为 `1.0`，同时记录备份中包含的工具模块。
- 当前导出备份只包含已编译且在“首页功能”中可见的业务模块；隐藏模块的数据仍保留在本地，并继续参与 CloudKit 同步，但不会进入这一次备份。导入时也只合并当前可见且已编译的模块；如果需要完整备份隐藏模块，应先在“首页功能”中显示它们后再导出。
- 当前只读取最新的本地容器和备份载荷结构，不再兼容更早的顶层 `VaultData`、旧体检嵌套批次或单选医疗机构字段。
- 备份密码至少 8 位；密码页默认填入当前管理员密码，也可以清除后输入独立的自定义备份密码。自定义密码不会由 App 保存，丢失后无法解密备份。
- 导入备份采用增量合并，不会清空未包含在备份中的工具模块或本地数据。备份中包含的模块按记录 ID 合并：已有同 ID 记录使用备份内容更新，新记录追加；对应的健康附件、信用卡账单、美食图片、保密资料附件和证照附件会一并恢复。
- 可在“我的 > 设置 > iCloud 同步”中主动开启 CloudKit 私有数据库同步；该功能默认关闭。银行、银行卡、股票持仓、换汇、健康档案、医疗机构、美食记录、提醒、保密资料、证照、账单和附件按记录增量同步，多个设备需登录同一 Apple 账户。
- “我的 > 设置 > iCloud 同步”提供管理员专用的“重建 iCloud 数据”：先确认本机资料和加密备份，再删除本 App 的 `MyToolsData` 私有数据区及云端附件，随后以本机快照重新创建并上传；本地 Vault 和附件不会删除。其他设备升级到支持重建协议的版本后会自动暂停同步，仍在使用旧版本的设备必须先关闭同步；Apple 对历史版本和存储用量的回收可能延迟。
- 首页模块开关和排序会持久化到本机 `UserDefaults`；开启 iCloud 同步后，它们会作为应用偏好写入 CloudKit 私有数据库，因此重新安装后登录同一 Apple 账户并重新开启同步即可恢复。隐藏模块不会停止业务数据同步，只有“删除功能数据”撤回窗口内会暂时排除目标模块；关闭首页显示也不会因为快照缺失而删除云端历史。银行登录字段模板、各模块标签库、保密字段模板以及页面排序/筛选偏好也会随对应数据同步。
- 删除功能本地数据并完成撤回窗口后，iCloud 同步会对该功能已删除的 CloudKit 记录执行真正删除；本地仍保留轻量 tombstone 处理多设备删除冲突。iCloud 设置中的用量是服务器口径，可能在删除后短时间高于本机，直到历史记录/附件版本完成回收。
- 当前 CloudKit 使用稳定的实体键和单个私有数据区，不会因普通增量同步主动制造重复业务记录。iCloud 用量明显高于本机时，通常来自历史附件版本、已删除记录的服务端延迟回收、旧设备尚未完成删除对账或云端暂存变更；客户端不能直接删除 CloudKit 历史版本。管理员可以在“iCloud 同步”设置中受控重建本 App 的 `MyToolsData` 自定义 Zone，随后由本机快照重新上传；该操作不清空其他 CloudKit 容器或本地业务数据，但历史版本回收仍由 Apple 服务端处理并可能延迟。
- 编译配置可以让模块参与编译但默认不显示：在 `Config/Shared.xcconfig` 中将对应 `MYTOOLS_HIDE_*` 设为 `MYTOOLS_DEFAULT_HIDDEN_*`。该默认值只用于没有本地显式设置的新安装，已有本地设置和 CloudKit 远端偏好优先。
- 本地档案始终是离线数据源。股票行情、汇率缓存、诊断日志、管理员会话和设备认证状态不会上传；附件使用 `CKAsset`，业务 JSON 写入 CloudKit 的加密字段。体彩开奖内容仍是网络只读缓存，但赛事选择和自定义顺序等用户偏好会随应用设置同步。关闭同步不会删除本机资料。
- CloudKit 使用记录级增量对账：主线程只采集当前状态，JSON 编码与附件读取在后台完成；连续本地修改先用 2 秒防抖合并为一次差异计算，上传与拉取交给 `CKSyncEngine` 系统调度，只有手动“立即同步”才强制发送；股票报价字段属于设备本地派生数据，报价刷新只写本地档案，不触发全量业务快照；业务记录同步成功后会丢弃同步状态中的重复 payload 和 CloudKit system fields，仅保留摘要、待发送内容和附件元数据。`cloud-sync-state.json` 使用 LZFSE 压缩并排除系统备份，旧版 JSON 状态可自动读取；system fields 只在待上传/重试期间保留，避免大量账单把同步状态膨胀成本地第二份数据库。远端附件在业务记录可用后后台逐个恢复，避免启动时因全量编码或大附件产生卡顿和内存峰值。启动时会先检查构建包的 iCloud 容器 entitlement；没有有效签名能力的 macOS Debug 包（例如未签名构建或 Xcode 测试宿主）自动关闭 CloudKit，绝不创建 `CKContainer`，避免无权限初始化导致启动崩溃；正式 iOS/iPadOS/macOS 签名包仍按 entitlement 启用同步。
- 同步状态容量准则：已成功同步的活动记录只保留稳定记录键、摘要、版本时间和删除标记；payload 只为待发送/冲突重试记录保留，未编译模块的不透明数据才允许作为恢复所需的离线 payload 留存。数据量增长后本地状态按记录数线性增加轻量元数据，而不会按业务 JSON 大小重复增长；CloudKit 服务端仍需保存完整业务 payload，这是跨设备恢复的必要数据，不应改成一个巨型聚合记录。
- 同步状态的读取、解压和旧格式迁移在 utility 后台任务执行，不能阻塞主线程创建首屏；同步 Worker 创建阶段不得直接读取几十 MB 的状态文件。

## 安全边界

- 本地 JSON 档案（`local-vault.json`）已使用 AES-GCM 静态加密，密钥保存在 Keychain 且不随备份/迁移转移；密钥丢失时档案不可读，只能通过 `.mytools` 加密备份恢复。图片与 PDF 附件仍以未加密文件单独存放在同一 Application Support 下（iOS 文件使用系统文件保护），附件加密尚未实现。
- App 沙盒隔离和敏感信息界面遮罩不能替代应用层加密；管理员密码现在以加盐 PBKDF2-HMAC-SHA256（210,000 轮）摘要保存在 `UserDefaults`，旧版无盐 SHA-256 摘要在下次验证成功后自动迁移为加盐格式。
- 导出备份文件经过密码加密；默认使用管理员密码，用户可以清除默认值并设置独立备份密码。管理员密码哈希保存在 `UserDefaults`，可用的明文备份密码会尝试保存在本机 Keychain 中以支持生物识别后的默认填充。
- CloudKit 同步是可选的数据副本与多设备合并能力，不能替代独立的 `.mytools` 加密备份。切换 Apple 账户，或用户从 iCloud 清除方寸数据时，App 会保留本机资料并自动关闭同步，避免误传到其他账户或重新上传已清除的数据。

## 打开与运行

1. 在 Xcode 中打开 `MyTools.xcodeproj`。
2. 选择 Scheme `MyTools`。
3. 本仓库默认配置使用作者的 Bundle Identifier，Xcode Cloud 可直接据此归档；其他开发者在真机安装前，应把 `Config/Signing.local.xcconfig.example` 复制为 `Config/Signing.local.xcconfig`，填写自己的 `DEVELOPMENT_TEAM` 和唯一 Bundle Identifier。
4. 在 Apple Developer 与 Xcode 的 Signing & Capabilities 中为这个 Bundle Identifier 启用 iCloud/CloudKit、Push Notifications 和 Background Modes，并创建 `iCloud.<你的 Bundle Identifier>` 容器。`MyToolsRelease.entitlements` 会按构建时的 Bundle Identifier 引用该容器。
5. `Signing.local.xcconfig` 不会提交到 Git。仓库中的 `Shared.xcconfig` 保留本 App 的默认 Bundle Identifier，其他开发者使用本地配置覆盖它；Team ID 和签名证书仍由 Xcode Cloud 或本机签名设置提供。
6. `Config/Shared.xcconfig` 中的 `MYTOOLS_ENABLE_*` 行是业务模块唯一编译开关，注释某一行即可构建不含该模块代码、页面、服务注册、备份和 CloudKit 参与逻辑的产品变体；`MYTOOLS_COMPILED_FEATURES` 由这些开关汇总生成，不要在其他构建设置中维护第二份清单。需要“编译但默认隐藏”时，配置对应的 `MYTOOLS_HIDE_* = MYTOOLS_DEFAULT_HIDDEN_*` 行；`MYTOOLS_DEFAULT_HIDDEN_FEATURES` 会自动加入 App 和测试 Target 的 Swift 编译条件。
7. 选择 iPhone、iPad 或 My Mac 后运行。

首次开启同步后，用开发签名运行 App 并新增或修改一条记录，确认 CloudKit Dashboard 的 Development 环境出现 `MyToolsEntity` 记录类型和 `MyToolsData` 自定义 Zone。上传 TestFlight 或 App Store 前，必须在 CloudKit Dashboard 执行 **Deploy Schema Changes to Production**；否则开发环境正常而正式版本无法读写。

Xcode Cloud 上传 TestFlight 构建时，会读取与 `MyTools.xcodeproj` 同级的 `TestFlight/WhatToTest.zh-Hans.txt`，自动填写简体中文“测试内容”。该文件采用静态维护方式，每次触发正式 TestFlight 构建前应先更新并提交；它不会修改已经上传的旧构建，也不是 App Store 版本页的“此版本中的新内容”。

首次使用建议：先进入“我的”设置管理员密码，再从“金融账户”“股票投资”和“健康档案”录入数据，最后导出一份 `.mytools` 备份。

## 架构边界

- `Core` 保存不归属于单个可关闭工具模块的基础能力；基础能力不能依赖某个业务模块的可见状态。
- `Features/*/Domain` 只保存业务模块的 Codable 数据和可确定计算，不直接访问文件、网络或 SwiftUI 状态。
- `AppStore` 是主线程上的应用状态协调器，负责把编辑结果交给持久化、附件和行情服务；页面不直接写本地文件。
- `SecureStore` 负责本地 JSON 的读写，`VaultPersistenceCoordinator` 在串行后台队列合并写入，并把失败错误码回传给应用状态。
- `AttachmentStore` 负责单个附件的文件生命周期；备份处理器负责健康、金融、美食地图、保密资料和证照的附件映射，五个模块共用同一套文件安全属性和预览包装器。
- `AuthManager` 只负责管理员会话和身份验证，敏感信息查看使用独立的验证入口，不把查看权限混入编辑会话。
- 股票和换汇模块都可以使用基础牌价能力；只有两个模块均隐藏或未编译时才停止牌价刷新。首页可见性分别控制各自页面、提醒和模块专属后台任务；备份范围另由备份参与声明及当前可见性共同决定，隐藏模块当前不进入加密备份。
- 即时报价、历史行情和牌价服务分别承担网络请求与解析；看盘原始时序写入独立离线缓存，不进入 `AppStore` 的业务 Vault 或加密备份。
